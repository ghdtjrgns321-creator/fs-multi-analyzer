# 8. 차별점 · 특장점 · 한계

## 8.1 비교 표

| 관점      | 통상적 접근                       | 본 프로젝트                           | 차이가 만드는 효과                             |
| --------- | --------------------------------- | ------------------------------------- | ---------------------------------------------- |
| 계산      | LLM이 숫자를 직접 계산            | 결정론 코드/SQL이 계산, LLM은 해석만  | 숫자 환각 0, 재현성 확보(같은 입력=같은 답)    |
| 발견      | 규칙으로 이상 유형 전수 열거      | LLM이 발견, 코드는 tool DSL로 앵커    | 열거하지 않은 이상도 포착(열린 도메인)         |
| 관점      | 한 AI가 전부 판단                 | 6개 독립 관점 교차검증                | 관점 간 충돌이 신호("숫자 위험한데 주석 잠잠") |
| 근거      | LLM 서술을 신뢰                   | 모든 주장에 EvidenceRef 유효숫자 대조 | 근거 없는 주장은 grounded=False로 탈락         |
| 계정 지식 | 코드에 하드코딩                   | config YAML 외부화                    | 새 산업·계정은 코드 변경 없이 설정만 확장      |
| 커버리지  | 슬라이스 선택(positive selection) | 모집단=분석+제외+미설명 원장          | 조용한 드롭을 구조적으로 차단                  |
| 위험 등급 | High/Medium/Low 라벨              | 연속 우선순위 점수(컷 없음)           | "기준선 아래 숨는 분식"을 잘라내지 않음        |

## 8.2 특장점 (근거 필수)

**① LLM 단순 투입의 4약점을 구조적으로 제거** (WHY_NOT_LLM)
- 재현성: 매번 다른 답·숫자 환각 → `src/signals` 결정론 계산으로 고정
- 전수성: 토큰 한계로 일부만 → 전 계정·전 연도 결정론 스캔(`universal.scan_*`, 채점/quota 제거)
- 앵커링: 학습 선입견 → `grounding.py` EvidenceRef 유효숫자 대조
- 일관성: 회사마다 흔들림 → `config/` 15개 YAML 외부화(루트 6 + playbooks 9)

**② 멀티에이전트의 "반쪽"을 자각하고 극복** (HANDOFF_ROOT_REDESIGN)
- 초기엔 내부 3관점(numeric·flow·change)이 같은 CFS 패널만 봐 numeric으로 수렴했다("멀티에이전트가 쓸모없다"의 정체). 진단: 도구 축이 "CFS 본문 계정 전년 대비 변화" 한 축뿐이라 데이터 차원 다양성이 없었다. 해결: 데이터층 전면 개방(B안) — OFS 개방·주석 전량 투입·SCE 2D 편입으로 각 관점이 자기 차원의 데이터를 본다.

**③ 진짜 가치는 전처리 엔진** (DISCLOSURE_DECOMPOSITION_DESIGN, FEATURES)
- LLM 전처리+Phase1을 2-Layer로 재정의했다 — Layer1(문서구조=목차 파트 축, 읽기)과 Layer2(분석 테마 축, 판단)를 분리. 자의적 taxonomy로 rich section을 억지 버킷하던 문제를 근본 해결. "재무제표를 읽을 수 있게 만드는 것"이 이 도구의 실제 자산이다.

**④ 재무제표 간 흐름 + 전기 대비 변화** (PLAN §1)
- 숫자만 보는 것이 아니라 BS-IS-CF를 9개 관계 사슬로 추적하고(공간 축), 전기 대비 변화·주석 텍스트 변화를 occurrence_state·series_normalize로 전담한다(시간 축). "숫자는 그대로인데 주석 문구가 커졌다" 같은 수치 vs 텍스트 교차가 핵심 신호다.

**⑤ 감사기준서에 앵커링된 방법론** (AUDIT_BASIS·METHODOLOGY)
- 관점·지표·신호 축(self 4축)이 ISA/KSA·K-IFRS 조항에 1:1 매핑된다(delta→ISA320, trend→ISA520). 신호 축이 capex를 잡으려 발명한 fitting이 아니라 기준서 도출임을 증명해(PHASE1_AXIS_AUDIT_MAPPING) 과적합을 방어한다.

**⑥ 무결성을 구조로 강제** (coverage·onboarding_gate·rebuttal)
- 커버리지 원장(모집단=분석+제외+미설명), hollow-PASS 차단(빈 검사=FAIL), silent drop 0(탈락도 reason과 함께 반환), 카드 제거 0(반박은 강등만). "조용히 맞는 척"을 코드가 물리적으로 막는다.

**⑦ 외부 정답 골든 테스트** (golden/)
- 자기 이전 실행을 정답으로 봉인하면 버그까지 잠긴다. 정답을 DART(수치)와 현실의 제재·재작성(적중)에서 가져오는 2검사로 상시 검증한다(9장).

## 8.3 한계 · 트레이드오프 (정직하게)

이 도구는 부정을 판정하거나 운영 탐지 성능을 보장하지 않는다(PLAN §15). 아래 한계를 문서에 그대로 명시한다(LIMITATIONS).

| #   | 한계                           | 성격                                                                                                       |
| --- | ------------------------------ | ---------------------------------------------------------------------------------------------------------- |
| 1   | 외화 재무 제외                 | 게이트가 차단(환산 안 함=시점 다름). 설계상 배제                                                           |
| 2   | 전처리 LLM 의존                | 회사당 ₩300~800·2~5분 비용                                                                                 |
| 3   | 서술형 감사관심(소송·특수관계) | LLM 전처리의 Layer1 리더가 추출 — 실패·0건 강행 시 누락(경고로 표면화)                                     |
| 4   | 게이트 경계                    | 단일 회사 시계열 범위, 수집 실패 표기 미완                                                                 |
| 5   | 부정 확정 안 함                | 설계 원칙(포지셔닝)                                                                                        |
| 6   | Phase2 실호출 비용             | 대주 ₩1,365·158초 — 운영 전수는 안 함                                                                      |
| 7   | 데이터 범위                    | 분기 제외·2015 이전 미수집·금융업 구양식(2020~22) 미제공·금융사 Phase2 E2E 미측정·정정공시 provenance 미완 |
| 8   | 주석 숫자표 신규/소멸 미지원   | 분류 축이 매년 재편돼 오탐 34~64%(D18, YAGNI). 계정·SCE·서술형은 지원                                      |

핵심 트레이드오프는 **점수 경계**다(WHY_NOT_LLM). BS·IS만 결정론 점수를 매기고, CF·포괄손익·소급재작성은 원래 출렁이는 항목이라 LLM 맥락 판단으로 넘긴다 — 멀쩡한 회사를 오해하지 않기 위한 의도적 보수다. 또한 백테스트 strict recall이 1/6~2/6에 그치는 것은 결함이 아니라 역할 분담의 결과다: 결정론은 발굴기, 판별은 LLM 층. "6/6을 억지로 되찾지 않는다"는 오버피팅 회피 원칙이다(BACKTEST_ANALYSIS).
