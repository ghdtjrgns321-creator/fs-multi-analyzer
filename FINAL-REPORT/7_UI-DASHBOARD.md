# 7. L5 대시보드 (Streamlit)

> **위치**: 파이프라인 종착. L4 카드 목록을 감사인이 보는 화면으로 렌더한다. 계산은 `src/report`, 순수 데이터 가공은 `card_data`, 렌더는 `card_view`/`report_html`로 SRP 분리한다.

## 7.1 내부 흐름 — 상태머신

```
회사명 검색 (OpenDART ~12만사 substring)
   │
   ▼
company_state 판정
   ├─ A 미수집        → "수집부터" 안내
   ├─ B 수집됨·미준비  → prepare_company (재정규화·주석분류·게이트·마커)
   └─ C 준비완료      → LLM 전처리(카드 단계 진입 조건) → 분석
                          │
                          ▼
              build_company_report (Phase1, 결정론)
                          │  Phase1 지표는 UI 미표시(내부 중간산출물)
                          ▼
              build_suspicion_cards (Phase2, asyncio)
                          │  save_cards 영속화 → 재방문 시 재실행 방지
                          ▼
              의심건 카드 목록 렌더 (3섹션 + 반박)
```

## 7.2 구조

| 구성요소           | 개수·값                                     | 출처                           |
| ------------------ | ------------------------------------------- | ------------------------------ |
| dashboard 모듈     | 9                                           | `dashboard/`                   |
| 회사 상태 분류     | 3 (A 미수집·B 미준비·C 준비완료)            | `prep.company_state`           |
| 카드 섹션          | 3 (주장·결과분해·시각자료) + 반박           | `card_view.py`                 |
| 차트 타입          | 3 (분해=발산막대·관계=지수라인·계정=추이바) | `card_view.py`                 |
| 별칭 자동등록 임계 | 0.7                                         | `AUTO_REGISTER_MIN_CONFIDENCE` |
| 분석 윈도우        | 5년                                         | `ANALYSIS_WINDOW_SPAN`         |

## 7.3 카드 3섹션 + 반박

카드는 통일된 3섹션 구조다(사용자 피드백: "반박만 보여 뭐라는지 모름" → 주장·수치가 카드에 실려야 사실 확인 가능):

1. **① 무엇이 의심스러운가** — 관점 주장(claims: perspective·description·cited_value)
2. **② 결과 분해(왜 움직였나)** — 변동분해 표(재귀 들여쓰기·미설명 잔차 정직 표시·잔차>20% 경고) + 기여율 셀 색농도 + 근거 수치 표(grounding 대조 수치, 분해 표 밖 항목)
3. **③ 시각자료** — 타입별 차트
4. **④ 반박** — 반대근거·정상설명·확인질문·다음절차 + verdict 라벨

카드 본문 순서는 조사결론 → 검토포인트(두괄식) → ①주장 → ②결과분해 → ③시각자료 → ④반박이다. 카드 첫 줄의 "🔎 검토 포인트"는 LLM 없이 결정론으로 생성된다(`card_data.review_point`) — "매출 −6.7%인데 영업이익 −62.8%"처럼 부모 대비 변화율 괴리 배수 ≥2일 때만 명제화한다.

## 7.4 차트는 타입별로 분기 (dataviz 폼)

카드 성격에 맞는 차트를 코드가 고른다(`card_view.py`):

| 카드 타입 | 차트                                     | 이유                                                                                              |
| --------- | ---------------------------------------- | ------------------------------------------------------------------------------------------------- |
| 분해 카드 | **발산 가로막대**(`contribution_figure`) | 0 기준 좌우 발산(왼쪽 빨강=하락/오른쪽 초록=방어), 토네이도 정렬 — 워터폴이 큰 감소를 오독해 교체 |
| 관계 카드 | **지수화 라인**(`legs_figure`)           | 첫 관측=100 지수화, 2다리면 tonexty 음영으로 괴리 강조                                            |
| 일반 계정 | **추이 바**(`trend_figure`)              | 당기 진한색 + YoY% 라벨, y축 눈금 숨김(막대 직접 라벨)                                            |

색상 팔레트는 dataviz palette validator를 통과했다(CVD 색각 이상 대비 ΔE 24.2). 금액 축약(`fmt_krw`·`humanize_amounts`)은 렌더 시점에 적용돼 캐시 카드에 즉시 반영되며, 1억 미만·연도·%는 불변으로 둔다.

## 7.5 LLM 전처리 — 자동 실행, 사람 확인은 보류분만

메인 화면의 [LLM 전처리] 버튼은 `run_full_onboarding`으로 게이트 재검문 → Layer 1 본문 통독(서술형 감사관심 → `report_extracts`) → 별칭 제안·자동 등록을 한 번에 실행하고, 완료 마커(`onboarding.json`)를 남겨 재실행을 요구하지 않는다 — 이 마커가 검증(카드) 단계 진입 조건이며, **완주(ok/empty)에만 기록된다**(실패 실행이 "✅ 완료"로 굳는 위장 차단, 11장 본문 통독 0건 오진). 같은 원칙이 카드 저장에도 걸려 있다 — 관점 실패가 있는 빈 결과는 `save_cards`가 저장을 거부해 이전 정상 카드를 보존한다. `auto_register_aliases`는 신뢰도 ≥0.7·비-기타 제안만 window 전 연도에 자동 등록하고(멱등), 등록이 생기면 5개년을 재정규화한다. Layer 1이 **완주하고 0건**이면 진입을 막지 않되 경고를 강제해 사람이 확인 후 강행한다(`can_enter_analysis`의 needs_override). 반면 **실패·미실행은 완료로 치지 않는다** — 마커를 안 쓰고 오류를 표시해 재실행을 남겨둔다(과거엔 실패도 "0건 완료"로 굳어 서술형 없이 분석이 진행됐다).

보류(저신뢰·기타)는 "기타 중요 계정" 경로로 흘러 라이브에선 금액>0이면 임계 없이 전부 게시되고(자산 5%↑ 임계는 backtest 도구 전용), 관점이 제기하면 `UNMAPPED_MATERIAL_ACCOUNT` 카드로 표면화된다. 사람이 버튼을 눌러 개별 등록하는 `_register_suggestion`과 수동 이탈 등록 폼은 메인 흐름에서 빠져, 별도 실행하는 정비 페이지(`dashboard/onboarding.py` 단독 구동)에만 남아 있다 — 보류분·교정용이다. `append_quirk`는 헤더 주석을 보존하며 안전 append(UTF-8 allow_unicode)해 mojibake 0을 지킨다.

## 7.6 hollow 렌더 방지 — 0건도 정직하게

빈 화면은 "위험 없음"으로 오해된다. 렌더러는 이를 막는다(`card_report`·`report_html`):
- 0건인데 관점이 failed면 "LLM 실패 — API 키 확인"(미검증과 위험없음 구분, §9)
- 0건이 정상이면 "검토 범위 내 위험 후보 없음"(검토한 계정·관점 수 명시)
- unaccounted>0면 "⚠ 커버리지 경고 N건 조용한 드롭"(커버리지 원장 표면화)
- blocked>0면 "관계사슬·재무비율 미진입 N건(금액)"(파생층 원장 표면화 — 계정 지표·카드에는 포함)

`report_view.py`는 API 미설정·데이터 부재·LLM 오류를 전부 안내로 흡수해 크래시를 금지하고, Phase1 지표(검토 큐·비율)는 내부 중간 산출물이라 UI에 표시하지 않는다.

## 7.7 실증 예시 — 아스트 카드가 화면에 뜨는 방식

2장의 아스트 재고자산 카드가 최종 화면에서 어떻게 보이는지 이어본다. 감사인이 "아스트"를 검색하고 2020년을 선택하면 상태가 C(준비완료)로 판정되고, 저장된 카드(`suspicion_cards.json`)가 있으면 LLM 재실행 없이 즉시 로드된다("저장된 검증 결과" 캡션). 저장은 무조건이 아니다 — **관점 실패가 있는 빈 결과는 `save_cards`가 거부**해 이전 정상 카드를 보존한다(11장 한도 소진 카드 파괴). 전 관점 완주 후의 진짜 0건은 저장한다: 빈 파일이 "실행됐고 후보가 없었다"는 증거이기 때문이다.

재고자산 카드는 계정 섹션 최상단(사전식 정렬 1위)에 뜬다. "재고자산 5년 4배 증가, 재고회전율 급락"은 numeric 관점(LLM)의 주장 문구다 — 결정론 검토 포인트(`review_point`)는 분해 기반 괴리 명제만 만들며, 분해 브리지 없는 BS 계정인 이 카드에선 비어 있다. ①주장에는 numeric·flow 관점의 description과 cited_value("168,532,992,835")가, 근거 수치 표에는 grounding 통과 수치가 실린다. ②결과분해는 재고↔매출원가 역행을, ③시각자료는 추이 바(2016~2020, 당기 진한색)를 보여준다. ④반박 섹션(카드 자체가 expander라 일반 섹션으로 렌더)에는 "수주 대비 선제 생산 가능"(정상 설명)·"재고 실사·평가충당금 확인"(다음 절차)이 담긴다. 감사인은 이 카드 하나로 주장·근거·차트·반박을 한 화면에서 검토하고 승인/기각/추가질문을 결정한다 — Human-in-the-Loop의 종착점이다.
