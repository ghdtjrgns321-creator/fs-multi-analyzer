# 9. 검증 (골든 2검사 · M/N) · 의사결정 (ADR)

> **적용 범위** — 비금융 일반 상장사(제조·판매·건설, K-IFRS 연결). 관계사슬 11·재무비율 15·변동분해 6이 매출–매출원가–재고–공사진행 재무구조를 전제하므로, 금융·보험·지주·리츠 등 이질 계정구조 업종은 미대응(신호 불성립). 아래 정답지 사건도 전부 비금융이다. 기간: 연간만(분기 제외)·2015 이전 미수집. 전체 한계는 [8장](8_DIFFERENTIATION.md).

## 9.0 검증 스코어카드 — 무엇이 보장되고 무엇이 "정답 부재"인가

이 도구는 부정을 확정하지 않으므로 단일 "분식 recall/FP" 성능표는 오히려 포지셔닝 위반이다. **정답(ground truth)이 존재하는 축만 수치화하고, 없는 축은 "측정 안 함"으로 남긴다**(가짜 정밀도 회피).

**정답이 있어 검증한 것 (2)**

1. **수치 충실도** (정답: DART 원천값) — 최종 카드에 찍힌 수치를 원천값과 전자동 대사. **LG생활건강 72/72·아스트 59/59** 전량 일치, 환각(value_mismatch)·변환오류(convert_fail)·대사불능(unreconcilable) **0**. 검사2 교차 대사(셀트리온 N=28)도 전량 0. → 표시 수치에 날조 없음. 아스트 수치는 2026-08-01 정체 마스킹 실행 카드 기준이다(정체 공개 실행 산출물은 혼선 방지로 폐기).

2. **제재 적중** (정답: 증선위/법원 확정 분식 **6사**) — 정답 계정이 카드 큐 상위에 뜨는지 recall@K로 채점한다. 정답 계정의 분식연도 이상강도로 사전 스크리닝(`golden/hit/_effect_ranking.md`)해 상위 **아스트(1위)·셀트리온(3위) 2사를 실행**했고 둘 다 포착(아스트 재고자산 rank1·recall@5=2/3, 셀트리온 분식벡터 2/2). 나머지 4사 미실행은 채점 0점이 아니라 스크리닝 후순위다 — 모델솔루션(소형사 유의성 낮음)·디아이동일(연결범위 분식, 원시강도 89.4%는 매칭 아티팩트)·두산에너빌리티(건설 진행률 특수계정 정규화 커버 갭, `runnable:true`이나 저효과)·세토피아(BS-only 금융자산·부채, 손익·추세 무영향). 표본 극소, 순위는 LLM 회차 편차 있음.

**정답이 없어 측정하지 않는 것 (1)**

3. **검토 큐 정밀도(FP)** — 오탐률은 정답 부재라 측정하지 않는다. 이상변화 큐가 목적이라 FP 개념 자체가 부적합하다. 예: 정상사 삼성에서도 이상신호 14건이 뜨지만 이는 오탐이 아니라 정당한 이상변화(당기순이익·차입금 등)다.

## 9.2 골든 테스트 — 외부 정답 2검사

"내 이전 실행을 정답으로 봉인하면 버그까지 잠긴다"(golden/DESIGN.md). 정답을 DART(수치)와 현실(제재·재작성)에서 가져온다.

**검사1 수치 골든** (`golden/numeric/check_numeric.py`) — 최종 카드(모든 변환 후)에 찍힌 수치를 DART 원천값과 전자동 대조. grounding이 못 보는 변환 버그(억/조 환산 ÷10·부호)를 겨냥한다. 판정 4종:

| 판정           | 의미                                            |
| -------------- | ----------------------------------------------- |
| match          | 원값 실재 + 환산 정합                           |
| value_mismatch | 계정 있으나 인용 금액 없음(환각)                |
| convert_fail   | 원값 맞으나 표기 스케일 불일치(÷10)             |
| unreconcilable | 계정 인덱스 미존재(조용히 통과 금지, 별도 버킷) |

**검사2 의심 적중 골든** (`golden/hit/check_hit.py`) — as-filed 원본 입력으로 파이프라인을 돌려 실제 제재·재작성 계정이 카드 큐에 뜨는지 recall@K·순위로 채점. 텍스트 비교 금지, 존재+순위만(비결정론 LLM 문구 변화에도 안정). 전후꼬임 차단(입력=원본 rcept 고정, DB값==asfiled 게이트).

## 9.5 Phase1 감사 하니스 — LLM 확률성 보완

정규화 버그는 코드 오류가 아니라 **예상 못한 입력 변형**(표준코드 없는 동명계정·주식보상을 배당 슬롯에·SCE 부호 제각각·정정공시가 원본을 덮음)이다 — 회사를 밟아야 발견된다. LLM 검사의 확률성을 4장치로 보완한다(P1_AUDIT_HARNESS):

1. **기계 바닥**(floor): 빈 것 = 통과 아니라 FAIL(hollow 차단)
2. **판정 매트릭스**: 회사×6차원, 근거 인용 강제, 안 본 칸=빈칸이 물리적으로 드러남
3. **전용 감사 에이전트**(p1-auditor): 기만 패턴 내장
4. **발견 즉시 기계화**

방법론도 전환됐다 — 라운드별 식 추적에서 전수 홀리스틱 통독으로. 작은 표본의 "수렴"은 착시였다(16번째 회사 후 105사를 더 봐도 신규 결함 0 = 진짜 수렴). 초기 자동 플래그 13~16건은 전부 거짓양성이었고, 원인은 phase1이 아니라 추적표(도구)의 사각 3종(SCE 2D 별도 테이블 미조회·CIS→IS 통합신고 미인식·배당 −abs 절대값 비교)이었다 — "도구 경계 ≠ 감사 경계"의 실증이다.
