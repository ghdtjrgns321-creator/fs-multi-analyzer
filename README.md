## 개요

### 1. 프로젝트 소개

5개년 공시 데이터 기반 검토 대상 목록 자동 생성 도구

#### 실제 사용 스크린샷

**1. 회사명 검색** — OpenDART 등록사(118,578개) 검색 (종목코드, 비상장 태그 표기)

**2. 연도 선택 및 분석 실행** — 사업연도 선택 후 분석 실행 - 준비 → 점검 → 분석 → 산출 4국면 순차 수행

<p align="center"><img src="docs/images/ui-flow-2-prepare.png" width="860" alt="회사 선택 화면 — 분석 사업연도 선택, 분석 실행 버튼, 준비·점검·분석·산출 4국면 진행 표시"></p>

**3. 검토 목록 생성** — 재무제표 영역별 검토 목록 생성 (손익, 재무상태, 현금흐름, 계정 관계 등)

**4. 검토 목록 상세 조회** — 카드 형태로 제공 (결론, 검토 포인트, 무엇이 의심스러운가, 결과 분해, 시각자료, 반박과 확인 절차)

#### 분석 대상 및 포지셔닝

- 분석 대상 데이터 : 최근 5개년 연결 및 별도 재무제표, 주석(XBRL/사업보고서 본문), 사업보고서 원문
- 포지셔닝 : 감사인의 전문가적 판단을 돕는 공시 데이터 분석 도구

### 2. 문제 인식

#### 재무제표 전수 검토의 한계

- 방대한 검토 데이터 : 단일 기업 1개년(연결/별도, 주석, 사업보고서 등) 기준에 매년 시계열까지 더해져 검토량 증가
- 공시 정보 구조의 이질성 : 재무제표, 주석, 서술형 문서의 형식이 달라 수동 대조 시 정보 누락 위험
- 비표준화된 검토 방식 : 검토자의 역량, 경험에 따라 분석 결과 편차 발생

#### 범용 LLM 분석의 한계

- 재현성 : LLM 직접 연산 → 수치 환각 발생 위험
- 일관성 : 응답 생성 시마다 분석 논리와 방향 변동
- 정보 누락 : 원문 직접 투입 → 임의적 데이터 누락 발생 위험
- 비교 가능성 : 회사별, 연도별 비교 어려움

### 3. 프로젝트 기능 및 기대 효과

| 기능                       | 기대 효과                                                                      |
| -------------------------- | ------------------------------------------------------------------------------ |
| 코드 기반의 사전 수치 연산 | 100% 수치 재현성 확보 및 LLM 환각 차단                                         |
| 데이터 전수 스캔           | 5개년 전체 계정 전수 분석 → 유의미한 항목만 검토단계로 승격                    |
| 검토 관점 고정             | 재무 수치, 주석, 계정 간 관계, 시계열 추세, 업종 비교 5가지 고정 에이전트 분석 |
| 사실 대조                  | 생성된 검토 카드 ↔ 사업보고서 원본 금액 자동 비교 후 불일치 항목 탈락          |
| 검토 결과 규격화           | 기업 및 연도와 무관하게 동일한 UI 구조 제공 → 비교가능성 제고                  |

#### 핵심 설계 원칙

- **연산/분석 역할 분리**
  - 코드 연산 : 증감률, 비율, 기여도 등 수치 연산은 알고리즘으로 처리 → 수치 환각 가능성 원천 차단
  - LLM 분석 : 코드로 산출된 결과값을 받아 의미 해석 및 주요 쟁점 식별
- **분석 관점 고정, 동적 데이터 라우팅**
  - 분석 관점 고정 : 병렬 분석 에이전트(재무 수치, 주석, 계정 간 관계, 시계열 추세, 업종 비교)로 검토 일관성 유지
  - 동적 계정 유입: 계산 엔진 연산 결과에서 검토가 필요한 계정만 병렬 분석 에이전트 단계로 유입
  - 외부 검증 절차: 검토 카드 확정 후 외부 검증 에이전트 실행 → 검토 카드에 분석 지표로 더해짐
- **에이전트 간 결과 격리**
  - 독립 실행 : 타 에이전트의 분석 결과와 주장을 입력으로 받지 않음
  - 격리 이유 : 에이전트 간 확증 편향 오염 차단
  - 집계 방식 : 병렬 분석 5개 에이전트들의 교집합순 정렬 → 검토 우선순위 결정
  - 후속 에이전트 : 조사, 반박, 외부 검증 결론을 해당 카드에 독립적으로 생성 → 우선순위 미개입
- **원본 대조를 통한 환각 차단**
  - 사실 대조: 결론에 인용 및 서술한 금액 데이터를 원 단위로 복원하여 실제 장부 데이터 대조
  - 자동 기각 및 로깅: 존재하지 않는 계정, 잘못된 금액으로 도출된 결론 - 시스템 자동 기각, 탈락 사유 기록

### 5. 주요 성능 평가 및 실증 사례 분석

공시된 실제 부정 사례(아스트, 2020년)의 정정 전 사업보고서로 End-to-End 검증 수행

- 사례 선정 기준 : 금융위원회 지적 확정 건 중 재무제표 수치 기반 탐지 가능한 사례 + 2015년 이후 시계열 데이터 보유 기업
- 타겟 계정 : 재고자산, 매출원가, 자본총계 (실행 전 타겟 계정 고정)
- 입력 통제 : 사후 정정된 데이터가 아닌 최초 DART 공시 사업보고서 투입
- 사전 지식 통제 : LLM의 사전 학습 정보 개입 차단
  - 마스킹 대상 : 회사명, 계열사명, 종목코드, 법인번호, 대표자명, 영문사명 + 외부 검색 에이전트 차단
  - 보존 데이터 : 계정명, 금액, 연도
- 핵심 검증 지표
  - 타겟 탐지 정확도 : 타겟 계정 - 최우선 검토 대상 목록에 식별
  - 수치 정합성 : 검토 카드에 인용된 금액 = DART 원장 수치


| 평가 항목        | 측정 결과                                                                 |
| ---------------- | ------------------------------------------------------------------------- |
| 입력             | 아스트 2020년 최초 제출본(정정 전), (시계열 분석 범위 : 2015\~2020년)     |
| 생성된 검토 카드 | [**총 24장**](#분석-대상-카드-도출-내역) (계정 13, 관계 4, 회사 7)        |
| 탐지 적중        | **2/3** — 재고자산(재무 수치, 시계열 추세 2관점), 매출원가(계정 간 관계)  |
| 미적중           | 자본총계 — 재고자산, 매출원가 왜곡 → 당기순이익 과대 계상 인과관계 미도출 |
| 수치 정합성      | **59/59 일치**, 환각 환산오류 없음                                        |

## 2. 실증 예시

아스트의 2020년 사후 정정 전 최초 공시 원본을 파이프라인에 투입하여 End-to-End 검증을 수행<BR>
사전 지식 통제를 위한 마스킹 적용, 총 24장의 검토 대상 카드 도출

### 사건 개요

- 회계 처리 오류 : 판매 완료 재고자산을 매출원가로 대체하지 않고, 가공의 재고자산을 보유 중인 것으로 과대 계상
- 재무제표 왜곡 : 기말 재고자산 과대 계상 → 매출원가 과소 계상 → 당기순이익 과대 → 이익잉여금 누적으로 자본총계 과대
- 타겟 계정 : 재고자산, 매출원가, 자본총계

### 분석 대상 카드 도출 내역

| 재무제표 영역  | 계정 카드                                                        | 관계 카드                          | 회사 카드                                 |
| -------------- | ---------------------------------------------------------------- | ---------------------------------- | ----------------------------------------- |
| **재고, 원가** | 재고자산                                                         | 매출↔매출원가↔재고자산             | 재고 체류 장기화·재고효율 저하            |
| 자산 평가      | 무형자산, 이연법인세자산                                         | —                                  | 무형자산 손상평가                         |
| 부채, 유동성   | 유동성장기차입금, 유동부채, 장기차입금, 단기차입금               | 차입금 조달↔상환↔재무활동CF        | 조기상환청구권 포함 전환사채와 단기유동성 |
| 현금흐름       | 단기차입금증가, 영업활동CF, 유형자산취득, 투자활동CF, 재무활동CF | 당기순이익↔영업CF, 이자지급↔재무CF | 이익의 현금화 저하                        |
| 자본           | 이익잉여금                                                       | —                                  | 자본성 조달 반복과 후속 BW 발행           |
| 우발, 특수관계 | —                                                                | —                                  | 종속회사 차입 연대보증                    |
| 이익, 세금     | —                                                                | —                                  | 수익성 급락                               |
| **합계**       | **13**                                                           | **4**                              | **7**                                     |

회사 카드는 계정이 특정되지 않는 지적으로, 재무제표 영역별 1장으로 병합된다

**타겟 계정 탐지 결과 분석**

| 타겟 계정 | 도출 카드 유형               | 탐지 결과                                                               |
| --------- | ---------------------------- | ----------------------------------------------------------------------- |
| 재고자산  | 계정, 관계, 회사             | 재무 수치와 시계열 추세 에이전트가 각각 지목                            |
| 매출원가  | 관계(매출↔매출원가↔재고자산) | 계정 간 관계가 세 계정의 증감 괴리로 지목                               |
| 자본총계  | 미적중                       | 재고자산, 매출원가 왜곡으로 인한 당기순이익 과대계상 인과관계 도출 실패 |

### 3-1-2. 계정 정규화

> **실제 구현**
> - 정규화 : [`mapper.py`](src/normalize/mapper.py), [`pipeline.py`](src/normalize/pipeline.py)
> - 표준 사전 : [`canonical_accounts.yaml`](config/canonical_accounts.yaml)

#### 도입 배경

- **기업별 비표준 태그 사용** — DART 제공 XBRL 택소노미를 사용 하지 않고 기업 자체 개별 태그 생성으로 식별 불가 문제 발생
- **연결/별도 기준 간 데이터 파편화** — 연결 및 별도 재무제표에 동일 계정 데이터 분산 공시 → 금액 이중 계상 및 누락 위험
- **데이터 타입 혼재** — 원화 외에 주식 수, 백분율(%), 서술형 텍스트 등이 혼재 → 연산 오류 위험

#### 표준 계정 사전 구축

**IFRS 국제표준 + 금감원 DART 확장 택소노미의 표준 ID**를 근거로 계정 2,017종 등재

```yaml
매출채권:
  statement: BS
  account_ids: # 표준 ID (사전 전체 2,766개)
    - dart_ShortTermTradeReceivable # 금감원 DART 확장
    - ifrs-full_CurrentTradeReceivables # IFRS 국제표준
  aliases: [매출채권] # 국문 계정명 (사전 전체 1,805개)
```

#### 단계별 매핑

| 단계           | 매핑 근거           | 주 적용 대상                               |
| -------------- | ------------------- | ------------------------------------------ |
| 1. 식별자      | 표준 ID 일치        | DART 택소노미를 따른 공시                  |
| 2. 국문 계정명 | 정규화 후 별칭 일치 | 자체 태그를 쓰되 계정명은 관행을 따른 공시 |
| 3. 미매핑      | 1, 2 모두 불일치    | 회사 고유 항목                             |

- 재무제표 간 오배정 방지 : 국문 명칭 → 복수의 재무제표에서 중복 사용되는 경우가 많았음 (예: 현금흐름표 데이터가 자본변동표로 라우팅되는 현상 방지)
- 기업의 임의 라벨링 통제 : 기업마다 한글 항목명이 달라 변동 없는 고유 번호(ID) 우선 매핑
- 오류 추적 가능 : ID 우선 매핑, 충돌 시 로그 생성으로 오류 추적 가능
- **예외 - 자본변동표** : 표준 ID 슬롯에 기업이 임의의 변동 내역을 기재하는 예외 케이스 다수 발견 → 국문 라벨 매핑 우선

#### 미매핑 계정 처리

- 표준 계정 사전을 대조 대상으로 사용 : 기업이 자체 태그를 생성해 표준 계정에 없는 ID와 국문 계정명 사용 시 미매핑 계정 처리
- 계정명 유지 : 미매핑 계정 → 회사가 공시한 계정명으로 검토 목록에 표시
- 추가 매핑 : [3-2-2. 데이터 보정](#3-2-2-데이터-보정)에서 LLM 재매핑

#### 도입 배경 및 설계 방향

| 구분 | 요약                                | 상세                                                                            |
| ---- | ----------------------------------- | ------------------------------------------------------------------------------- |

| 사업연도   | 회사연도 | 주석 개념 없음 | 주제 적중 건수 |
| ---------- | -------: | -------------: | -------------: |
| 2015\~2019 |       55 |           100% |              0 |
| 2020\~2022 |    1,884 |          99.7% |             32 |
| 2023       |      716 |          22.2% |        381,170 |
| 2024\~2025 |    1,959 |             0% |      1,795,097 |

주석 개념이 없는 사업연도는 [3-1-4. 본문 서술 추출](#3-1-4-본문-서술-추출)이 사업보고서 본문에서 주석을 확보한다

#### 주제별 분류 로직

- 입력 데이터 : 개념, 라벨(국문, 영문), 기간, 단위, 값, 차원(부문/자산종류 등 분해 기준)의 7열로 구성된 XBRL 데이터
- 처리 로직 : 개념을 4개 유형으로 분류, 분석에 유의미한 데이터 선별 및 필터링

| 분류 기준   | 무엇인가                                 | 적재 여부                       |
| ----------- | ---------------------------------------- | ------------------------------- |
| 본표 중복   | 본표에 이미 나온 계정과 같은 개념        | 총계 제외 후 분해된 값으로 적재 |
| 표지 정보   | 감사인, 연락처, 문서 식별 등 비재무 정보 | 제외                            |
| 주제 적중   | 사전 정의된 주석 카테고리에 매핑된 개념  | 해당 카테고리 라벨을 붙여 적재  |
| 사전 미적중 | 어느 카테고리에도 분류되지 않은 개념     | 라벨 없이 원본 그대로 적재      |

- 미적중 데이터 무결성 보존 : 분류 및 필터링은 에이전트 탐색 최적화를 위해 라벨을 부여하는 과정 → 분류 실패분도 전량 적재
- 미적중 비중 : 전 코퍼스 4,614개 회사연도 기준 4.2%, 표준 택소노미 없이 기업이 자체 생성한 태그

**본표 중복 판정 — 회사 자체 생성 태그**

표준 택소노미를 쓰지 않는 기업은 재무상태표, 손익계산서, 현금흐름표, 자본변동표 행에 자체 태그를 붙인다. 이 태그는 표준 계정 사전과 대조되지 않아 주석으로 오분류될 수 있어, 태그가 명시한 소속 재무제표를 근거로 본표 중복 처리한다

- 판정 근거 : 80개 회사연도 대조 결과 당기 무차원 항목 1,413건 중 97.7%가 본표 수치와 계정명, 금액 모두 일치
- 판정 순서 : 표지 정보보다 먼저 판정 — 표지 판정용 문자열이 태그에 우연히 포함되면 부문별로 분해된 본표 항목까지 제외되는 문제 방지
- 예외 : 주석 소속을 명시한 자체 태그는 본표 중복에서 제외

#### 주석 본문 읽기

XBRL 주석은 2023년 이후 공시분에만 존재하므로, 그 이전 사업연도의 주석은 사업보고서 본문 "재무에 관한 사항"이 유일한 경로

| 처리      | 방식                                        | 근거                                                                            |
| --------- | ------------------------------------------- | ------------------------------------------------------------------------------- |
| 분할      | 글자 수 기준 6만 자, 중첩 3천 자            | 대단원 최대 66만 자로 1회 투입 불가, 목차 서식이 35종이라 정규식 분할 폐기      |
| 연결/별도 | 추출 항목마다 연결, 별도 구분 부착          | 동일 주제가 연결과 별도로 2회 공시되어 축 없이는 서로 다른 수치가 중복으로 오인 |
| 중복 제거 | 같은 구분, 인용 금액 일치율 0.9 이상만 제거 | 총계 항목과 세부 내역의 일치율이 0.4\~0.5로, 임계를 낮추면 세부 내역 소실       |

- 실측(삼성전자, 두산 2024년) : 추출 217건, 인용 금액 916건 전량 원문 실재
- XBRL 미수록 항목 포착 : 사채 재무특약, 기한이익상실 조항, 콜옵션 행사 의결, 계열사 행정소송

| 구성 요소           | 상세 설명                                      |
| ------------------- | ---------------------------------------------- |
| 결론                | 식별 리스크 한 줄 요약 및 도출한 에이전트 이름 |
| 검토 포인트         | 결론 도출 근거                                 |

| 반박, 확인 절차     | 반대 가능성, 확인 질문, 다음 절차              |

#### 카드 생성 프로세스

| 단계 | 처리                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------- |
| 병합 | 동일 계정 내 지적사항 통합                                                                        |
| 흡수 | 단일 원인 하위 계정의 연쇄적 변동(매출원가 → 매출총이익 → 영업이익 → 순이익)을 최상위 단계로 흡수 |
| 조사 | 생성된 검토 카드 전량 조사, 관점에 종속되지 않은 독립된 에이전트                                  |
| 대조 | 반박 에이전트, 외부 검증 에이전트 실행                                                            |

#### 카드 정렬
  - 1순위 : 표수, 해당 주제를 지목한 에이전트 수
  - 2순위 : 금액, 1순위의 표수가 같으면 해당 주제의 계정 금액이 큰 순
  - 특이사항 : LLM 판단과 반박 에이전트의 판정은 순서에 미개입

#### 조사 에이전트
생성된 카드의 원인 추적 
  - 대상 : 생성된 카드 전량
  - 특이사항 : **관점에 종속되지 않은 상태에서 원인 추적**
  - 산출 : 결론, 원인, 이상 지점, 남은 확인사항, 규명 완결 여부 등
  - 예외 처리 : 결론 실패 시 조사 미수행 표시

#### 반박 에이전트
생성된 카드의 반대 의견 조사
  - 대상 : 생성된 카드 전량
  - 특이사항 : **생성된 결론에 영향 행사 불가**, 임의 카드 삭제 및 신규 생성 불가
  - 산출 : 반대 근거, 확인 질문, 필요한 다음 절차 등
  - 예외 처리 : 연산 실패 시 반박 미수행 표시

#### 외부 검증 에이전트

- 유효 출처 표시 : 출처 URL 결여 레퍼런스 → 자동 폐기
- 외부 수치 대조 : 외부 인용 금액을 정수 단위로 정규화 → 원본 수치 대조
- 예외 처리 : 검색 결과 없음 / 검증 미수행 구분 표시

## 5. 핵심 의사결정

### 데이터 분해 과정의 어려움과 해결방안

1. 계정 이름이 회사마다 다름
   - DART의 XBRL 태그를 지키지 않는 회사가 많고, 같은 계정에 임의 라벨을 붙임
   - 비교 가능성을 위해 **표준 계정 사전**구축
2. 숫자와 서술이 한 문서에 섞임
   - 재무제표, 주석, 본문 서술 등 기준 축이 다름
   - 하나의 적재 구조로 통일 되지 않음
3. 표마다 구조가 다름
   - 자본변동표는 자본거래 × 자본구성요소 2차원이라 1차원 계정 처리를 그대로 적용할 수 없음
   - 2차원 구조를 유지한 **자본변동표 전용 테이블**로 적재
   - 재무상태표 자본 항목과 대조 — 구성요소별 기말 잔액 합계를 재무상태표 자본총계와 검증
4. 회사, 연도별 표기 방식이 바뀜
   - LG생활건강 사례 : 계정명을 "투자활동으로 인한 현금유출액"에서 "투자활동으로부터의 현금유출"로 바꾸면서 표기 부호를 바꿈
   - 데이터에는 `2024 +1,666억 → 2025 −1,905억`으로만 남아 진짜 재작성과 구분되지 않음
   - **전기 값을 대조축으로 사용** — 절대값이 같고 부호가 달라진 경우 표기 변경 의심
5. 매핑 실패 계정
   - 회사 고유 항목(예: 신종자본증권변동)등 매핑 실패 계정 존재
   - **원문 이름을 유지한 채 "기타 중요 계정"으로 게시**하여 데이터 소실 최소화
