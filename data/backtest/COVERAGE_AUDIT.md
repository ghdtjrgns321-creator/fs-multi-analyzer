# DART 데이터 커버리지 전수 감사

> 목적: "재무제표를 전수로 본다"는 주장을 코드 경로와 실데이터로 검증한다. DART가 제공하는 모든
> 데이터를 수집(L0)→정규화(L1)→신호(L2)→관점입력 각 단계까지 계정 단위로 추적해, 무엇을 받고·보고·
> 버리는지 정량으로 못 박는다. LLM 호출 없음(결정론). 모든 수치는 실데이터 재현값이다.

## 0. 감사 방법·표본

- **표본 27사** = 분식 16사(known_cases_mega positive, runnable) + 정상 다양 10사 + 삼성전자(00126380).
- **재현 방식**: 감사 하니스(`data/backtest/_coverage_audit.py`)가 운영 코드(`src/signals/universal.py`,
  `src/normalize/pipeline.py`, `src/signals/config.py`)의 **실제 함수를 그대로 호출**하고 각 계정의
  단계별 운명을 계측한다. 별도 재구현이 아니라 운영 funnel에 계측만 삽입했다.
- **검증 앵커**: 하니스 산출 = 삼성 2025년 총 61계정 / floor통과 34 / floor미달 27(44.3%)로,
  사용자가 독립 측정한 "삼성 34/61"과 **정확히 일치**한다. 하니스의 신뢰성이 확인된 값이다.
  (아스트는 본 감사 재현값 OFS 기준 26/50이며, 사용자의 이전 측정 29/57과 다르다 — §5.4 참조.)

표본 회사 목록은 부록 A.

## 3. 재무제표 종류 (sj_div) — 표본 전수

표본 27사 전 연도·CFS+OFS 원천(finstate_all) 행수를 sj_div별로 집계하고, 정규화 후·신호단계 운명까지 추적.

```
sj_div   원천(raw)   정규화 후   universal스캔   설정사슬(mvp1)   순효과
BS       12,434      12,189      O               O               전면 사용
IS        1,591       1,579      O               O               전면 사용
CF       14,000      13,633      X(BS/IS로 좁힘)  O(CF canonical) 사슬 한정 사용
CIS       5,778       5,346      X               X               전면 미사용
SCE      14,728       2,811      X               X               전면 미사용(+dedup 81% 붕괴)
합계     48,531      35,558
```

- **신호엔진은 BS·IS만 스캔한다.** `universal.py:36` `scoped[scoped["sj_div"].isin(["BS","IS"])]`로 좁힌다.
- **CF는 "전면 누락"이 아니다.** universal 스캔과 single_yoy(`red_flags.py:121`)에선 빠지지만, mvp1 설정
  사슬(`relationship_chains.yaml`의 영업/투자/재무활동현금흐름 등 CF canonical 계정)에는 들어간다.
  → Claude의 "CF 누락" 주장은 **절반만 맞다**(§4 재확인).
- **CIS·SCE는 진짜로 전면 미사용.** canonical_accounts.yaml에 CIS·SCE statement 계정이 **0개**라 전부
  "기타 중요 계정"으로 떨어지고, 신호 스캔 대상(BS/IS)도 아니다. 기타포괄손익(재평가·해외환산·위험회피)과
  자본변동(증자·배당·자기주식·이익잉여금 처분)은 신호로 변환되지 않는다.
- SCE는 dedup이 81%를 접는다(14,728→2,811): 자본변동표의 member/차원 행이 대량 중복으로 처리됨.

## 4. 행 내부 필드 (컬럼)

finstate_all 원천 컬럼은 **18개**. 정규화가 읽는 것 7, 버리는 것 11.

```
컬럼                  정규화 사용         용도
rcept_no             버림
reprt_code           버림
bsns_year            사용 → year
corp_code            사용 → corp_code
sj_div               사용 → sj_div
sj_nm                버림
account_id           사용 → 1순위 매핑키
account_nm           사용 → label/2순위 alias 매핑
account_detail       사용(dedup 한정) → 연결/별도/[member] 점수, 그 뒤 drop
thstrm_nm            버림
thstrm_amount        사용 → amount (당기만)
frmtrm_nm            버림
frmtrm_amount        버림  ← 전기
bfefrmtrm_nm         버림
bfefrmtrm_amount     버림  ← 전전기
ord                  버림  ← 위계/순서
currency             버림  ← 통화
thstrm_add_amount    버림  ← 누계
```

`grep -rn 'frmtrm|bfefrmtrm|thstrm_add|ord|currency' src/` = **0건**. 이 컬럼들은 읽는 시점에 사라진다.

- **금액은 당기(thstrm_amount) 1개만 쓴다.** 시계열은 "여러 연도 보고서를 각각 수집·정규화해 concat"으로만
  구성된다. 한 보고서 안의 전기/전전기 컬럼은 버려진다.
- **통화(currency) 미사용**: 환산·검증 로직 없음. 외화 표기 행이 섞여도 그대로 가산(§8).
- **ord(위계) 미사용**: 계정 부모/자식 구조를 쓰지 않아, 소계-구성요소 관계는 canonical playbook의
  `is_subtotal` 플래그로만 부분 처리.

### ★ 재작성(소급재작성) 탐지 — 가능하지만 안 함

올해 보고서의 `frmtrm`(전기)과 작년 보고서의 `thstrm`(당기)를 대조하면 소급재작성이 잡힌다.
**코드에 이 대조가 없다**(frmtrm 미사용). 실데이터로 증명 — 아스트(분식: 재고자산 과대), OFS:

```
계정        연도   frmtrm(전기, N년보고서)   thstrm(당기, N-1년보고서)   차이
재고자산     2020       41,854,541,192          110,270,586,075       -68,416,044,883 (-684억)
자산총계     2020      362,101,269,703          450,128,808,728       -88,027,539,025 (-880억)
```

아스트의 2019년 재고는 2019년 보고서에서 1,102억으로 인식됐다가, 2020년 보고서의 전기 비교란에서는
418억으로 **684억 하향 재작성**됐다(자산총계는 880억 하향). 이 대조 한 줄이면 잡히는 재작성 신호를
현재 파이프라인은 frmtrm을 버려서 **전혀 보지 못한다.**

## 6. 신호 커버리지 (L2)

신호 유형은 **전부 "변화"(change) 기반**이다. "수준 이상"(absolute level)을 내는 신호는 없다.

```
신호 유형                근거                         성격
universal_yoy           전년 대비 50%↑               변화
universal_mix_shift     구성비 5pp↑                  변화
universal_z_score       4년 이력 대비 |z|≥2          변화
single_account_yoy      canonical YoY 50%↑          변화
growth_divergence       두 계정 증가율 괴리 15pp      변화
direction_mismatch      증가율 방향 vs CF 방향        변화
cfs_ofs_gap             연결-별도 금액 괴리 30%       구조(횡단)
```

- **"DIO 432일" 같은 절대 수준 이상은 신호로 안 난다.** `ratios.py`가 DIO/DSO/부채비율/이자보상배율 등을
  계산하지만, 이 값들은 **L4 리포트(company_report)·피어벤치마크에 숫자로 실릴 뿐** L2 red-flag로 임계
  판정되지 않는다. 분모/임계로 "수준이 비정상"을 거르는 결정론 게이트가 없다. 진행률 과대(두산·한화오션 유형),
  재고 진부화(DIO 폭증)는 그 수준이 전년과 비슷하면(이미 높게 유지) 변화 신호에 안 걸린다.
- **신규 계정은 YoY 자체가 불가**(전년 0/없음). 가공 목적의 신설 계정 라인은 YoY 사각.

DART 구조화 주석뷰어(singlnote)의 indCd별 카테고리를 직접 조회(독립 HTTP)한 결과:

## 8. 정규화 무결성

- **dedup 손실 26.7%** (48,531행→35,558행). 대부분 정보손실 아님:
  - SCE 81% 붕괴(14,728→2,811)는 자본변동표 member/차원 중복행 제거 — 정상.
  - BS·IS·CF·CIS는 행수 감소 2~8%로 소폭(동일 계정 연결/별도/[member] 중복 1행 대표 선택).
  - `_dedupe_canonical_rows`는 canonical당 1행만 남기되 **구성요소를 합산하지 않는다**(중복계상 방지).
    이로 인해 한 canonical에 여러 원천행이 있으면 대표 1행만 남고 나머지는 신호 대상에서 빠진다(설계상 의도).
- **통화 환산 부재**: currency 컬럼 미사용(§4). 외화 표기 행이 있어도 환산·검증 없이 그대로 처리.
  표본에선 대부분 KRW라 실해는 작지만, 환산 검증 로직이 없다는 사실은 명시한다.
- **미매핑(기타 중요 계정) 비율** (정규화 전체 행 기준, 전 연도·양 fs):
  - 분식사 평균 **65%** (범위 45~83%), 정상사 평균 **61%** (50~69%), 삼성 **42%**.
  - 미매핑이라고 분석 제외는 아니다: universal 스캔은 label을 scan_key로 series를 만들어 YoY/z/mix를 돌린다.
    다만 **관계사슬(relationship_chains) 교차검증에는 canonical만 참여**하므로, 미매핑 계정은 "변화 신호"는
    받되 "사슬 정합성"(매출-채권-CF 등)에선 빠진다. 미매핑율이 60~80%라는 건 사슬 검증의 모수가 작다는 뜻.

### 보강4. dedup이 버린 행 실물 (1차: "대부분 정보손실 아님" 단정 → 실측)

삼성 2024 CFS 213행 → `_dedupe_statement_rows` 후 135(78버림) → `_dedupe_canonical_rows` 후 128(7버림).

- **statement dedup 78행**: 거의 전부 **SCE member-차원 행**(기초자본·배당·연결실체내 자본거래 등이
  지배기업지분/비지배지분/연결 member별로 7행씩). 대표 1행만 남기고 구성요소 분해를 버린다 —
  정보손실 맞으나 SCE가 미사용이라 신호 영향 없음.
- **canonical dedup 7행 — 일부는 매핑충돌 정보손실(★ 1차 단정 오류)**:
  ```
  당기순이익      4행 모두 344,513억 → 진짜 중복(무해)
  자본총계        2행 모두 402조     → 진짜 중복(무해)
  지배기업소유주지분 2행: 391조 vs 50조 → 서로 다른 계정이 같은 canonical에 충돌, 50조 행 버림
  비지배지분순이익  2행: 12,481억 vs 8,299억 → 충돌, 작은 행 버림
  ```
  → "대부분 무해"는 맞지만 **매핑충돌로 금액이 다른 행을 버리는 사례가 실재**한다(alias가 BS 잔액과
  IS/포괄손익 라인을 같은 canonical로 끌어와 dedup이 큰 값만 남김). 1차의 "정보손실 아님" 단정은 부정확.

### 보강5. 미매핑(기타 중요 계정) 실명 (1차: 비율만 → 계정명)

sj_div별 미매핑율(전 표본): **BS 48% · IS 29% · CIS 56% · CF 80% · SCE 94%**.

canonical에서 빠진 **BS 핵심 계정**(표본 다수 등장, 금액 큼) — 변화 신호는 label로 받되 관계사슬 검증 불참:

```

투자부동산(19사) · 유동성장기부채(10사,최대22조) · 확정급여부채/순확정급여부채(9~10사)
당기손익-공정가치금융자산 · 기타유동·비유동금융자산 · 상각후원가측정금융자산
```

- **IFRS16 리스(사용권자산·리스부채)가 canonical에 통째로 없다** — 조 단위인데 관계사슬·비율에서 빠짐.
- **관계기업투자 alias 버그**: canonical은 있으나 라벨 "관계기업투자"가 alias 목록(관계기업 및 공동기업
  투자 등)과 안 맞아 미매핑. 이렘 분식(관계기업투자 과대 손상미인식) 계정이 미매핑으로 샐 수 있다.
