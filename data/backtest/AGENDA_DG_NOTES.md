# 주석(notes) 수집 현황·전수 수집 가능성 (AGENDA_DG_NOTES, D-G)

> 주석 디테일(무형자산·차입금·관계기업 등)이 사실상 비어 있는 원인과 전수 확보 가능성을 읽기전용으로
> 측정. 수집 실행·코드 수정 없음. 재현: `_dg_notes_scan.py` → `_dg_notes_scan.json`.
> 단정 금지 — 수집 방향 결정은 다음 단계(토의). 본 문서는 현황·옵션 제시까지.

## 1. 현황 수치 (전수)

분모(검사 회사연도) = **4,773** (MERGE_AUDIT 기준, 1,667사). raw 디렉터리 존재 기준으로 세면 5,116이나,
정규화 분석 대상으로 확정된 분모는 4,773을 사용(`MERGE_AUDIT.md:10`).

| 항목 | 회사연도 | 비율 |
|---|--:|--:|
| `raw/notes/` 디렉터리 보유 | 62 | 1.3% |
| `note_categories.json` 보유 | 62 | 1.3% |
| **실제 주석 내용 보유(빈 껍데기 아님)** | **3** | **0.06%** |
| 전부 빈 껍데기(HTML `<body>` 공백) | 59 | — |

핵심: "62개 수집"은 **디렉터리·파일이 생성된 수**일 뿐이고, 실제 표 데이터가 들어 있는 회사연도는
**삼성전자 3개 연도(2023·2024·2025)뿐**이다. 나머지 59개(분식 16사 전 연도 + 삼성 2022)는
OpenDART가 빈 페이지를 반환해 헤더만 있는 껍데기다.

- 빈 파일 실측: 아스트(00409681)/2019 8개 카테고리 `.txt` 전부 33바이트(헤더 한 줄), `.html` 576바이트(`<body></body>` 공백).
- 내용 있는 파일 실측: 삼성/2024 차입금(D82240) `.html` 87,237바이트 — 단기차입금 금액·담보·이자율 표 정상 수록.

### 카테고리 슬롯 단위 (8 code × CFS/OFS = 16슬롯/회사연도)

- 전체 슬롯 992 중 실내용 슬롯 **48 (4.8%)** — 전량 삼성.
- 삼성 연도별 실내용: 2022 = 0/16, 2023 = 16/16, 2024 = 16/16, 2025 = 16/16.

## 2. 62개 표본의 정체

62개는 무작위·전수 수집이 아니라 **백테스트 감사 표본에만** 수집된 것이다.

- 보유 회사 = **17사** = 분식 16사(전수) + 삼성전자 1사. 정상 10사는 **0개**.
- 분식 16사 교집합 = 16/16(누락 0), 감사 표본 외 추가 회사 = 0.
- 연도는 각 사의 백테스트 run 연도 구간(분식사 2015~2023, 삼성 2022~2025)에 분포.
- 수집 경로 = `src/collect/spike.py`의 `collect_company_years(include_notes=True)`를 감사 표본 회사에 돌린 결과.
  파일명 D-code 8종(D82210 유형자산·D82240 차입금·D82242 매출채권·D82245 사채·D82638 재고자산·
  D82757 충당부채·D83800 주당이익·D86120 자본금적립금)은 `note_categories.json`과 100% 일치.

> 즉 분식사 59개 회사연도는 "수집 시도는 했으나 OpenDART가 데이터를 주지 않아" 빈 껍데기로 남은 것이고,
> 삼성만 데이터가 채워졌다. 표본 자체도 17사로 편중(전체 1,667사의 1.0%).

## 3. 수집 파이프라인 현재 능력

### 코드 경로 (`src/collect/`)

```
spike.py  collect_company_years()         감사 스파이크. 기본 대상 = 삼성(00126380), 연도 2022~2025
  └ notes.py  NoteCollector
       categories(indCd)   POST  /disclosureinfo/fnltt/singlnote/searchAccountGubun.do  → 카테고리 목록
       detail_html(...)    GET   /disclosureinfo/fnltt/singlnote/listDetail.do          → 카테고리별 주석 HTML
  └ notes.py  write_note_detail()   html + BeautifulSoup 추출 txt 저장 + table_count 통계
```

엔드포인트 특성:
- **OpenAPI(키 기반)가 아니라 OpenDART 웹 조회 페이지**(`disclosureinfo/...`)를 `requests`로 직접 긁는다.
  `OpenDartReader`가 래핑하지 않는 비공식 경로(notes.py docstring 명시).
- `categories()` 기본 업종코드 = `XBR103`(비금융) 고정 → **8개 카테고리만**. 금융/보험 등 업종별
  카테고리(XBR101~107, 고유 70종)는 회사 업종에 맞춰 받지 않는다(`COVERAGE_AUDIT2.md:135-147`).
- `detail_html`은 `stlmTp=11011`(사업보고서), `stlmYr=연도`, `selectToc=CFS/OFS` 파라미터로 단일 페이지 조회.

### 능력 한계 (실측 근거)

1. **데이터 가용성이 거의 없음(최대 제약).** 이 구조화 주석 뷰어는 삼성급 대형사·최근연도에만
   값을 반환한다. 분식 16사 전 연도 + 삼성 2022가 빈 응답 → 4.8%만 채워짐. "전수 수집을 해도
   대부분 빈 페이지일 가능성"이 실측으로 확인됨(가설 아닌 관측).
2. **카테고리가 8종으로 한정.** 무형자산·개발비·관계기업투자·리스·사용권자산 등은 이 8종에 없다
   (`note_mappings.yaml`도 8 note_code만 매핑). 배경 메모(`_AUDIT_HANDOFF.md` §7)와 일치:
   "무형자산·개발비·관계기업 주석은 구조화 엔드포인트에 없음(원문 미수집)".
3. **업종 미반영.** 금융사는 XBR103 카테고리가 부적합 → 8종조차 안 맞음.
4. **rate·재시도 미구현.** 단순 `requests.Session`, 백오프·rate limit·실패 재시도 없음.
   웹 페이지 경로라 OpenAPI 일일 한도(2만건)와 별개지만 비공식 경로라 안정성 보장 없음.

### 대안 경로: XBRL 원본 zip

- `opendart.py save_xbrl_zip()`가 `finstate_xml`로 사업보고서 XBRL zip을 받는다. 이 zip은 **전체 주석을
  XBRL(TSV)로 포함**하므로 Arelle로 전개하면 8종 한계·빈 응답 문제를 우회할 수 있는 후보다.
- 현재 보유: **4개**(삼성 2022~2025)뿐. L1/L2에서 미사용(`COVERAGE_AUDIT2.md:21`).
- 즉 "주석 디테일 전수"의 기술적 현실 경로는 singlnote 웹뷰어가 아니라 **XBRL zip + Arelle 전개**일 수 있다(미검증, 다음 단계 확인 대상).

## 4. 전수 수집 가능성·비용·옵션 (단정 금지)

판단 전 확인 필요 사항(미검증):
- (확인A) singlnote 빈 응답이 "해당 연도 미제출"인지 "엔드포인트 자체가 소형사 미지원"인지 — 표본 추가 조회로 구분.
- (확인B) XBRL zip이 분식·소형사에도 존재하는지(가용성)와 zip 내 주석 TSV에 무형자산·관계기업이 실제 들어있는지.

| 옵션 | 내용 | 예상 비용 | 리스크/한계 |
|---|---|---|---|
| **O1. 보류(현행 유지)** | 주석 미사용 전제로 Phase 진행, 신호는 재무제표 본문 수치만 | 0 | 주석 기반 신호(담보·약정·소송·손상) 영구 부재 |
| **O2. singlnote 전수** | 4,773×16 ≈ 76,368 GET, 업종별 카테고리 확장 시 더 증가 | 네트워크 다수·수일 | **실익 낮음**(실측 4.8%만 채워짐). 소형사 대부분 빈 응답 가능성 큼 |
| **O3. 대상회사만 singlnote** | 신호 후보·관심 회사연도에 한정 | 중간 | 여전히 대형사 위주만 채워짐. 분식 표본이 대부분 빈 응답인 점이 치명 |
| **O4. XBRL zip + Arelle 전수** | finstate_xml zip 받아 Arelle로 주석 TSV 전개 | zip 다운로드 4,773건 + 전개 파이프라인 신규 | 용량·민감원문 보존 원칙 검토 필요. 단 8종 한계·빈응답 우회 가능성 — **가용성 선검증 필수(확인B)** |

권고 방향(참고용, 결정은 토의): 현재 singlnote 경로는 실측상 거의 빈 응답이라 O2/O3의 비용 대비 실익이
낮다. 주석 전수가 목표라면 O4(XBRL+Arelle)의 가용성을 소표본으로 먼저 검증(확인B)한 뒤 O1/O4 중
택하는 순서가 합리적으로 보인다. 다만 singlnote 빈 응답의 원인(확인A)을 먼저 가르는 것이 선행.

## 6. O4(XBRL zip + Arelle) 가용성 선검증·표본 수집 결과 (2026-06-08 실행)

> §1~5는 읽기전용 조사였다. 본 절은 후속 실행: O4 경로를 **실제로 검증·표본수집**했다.
> 신규 코드 `src/collect/notes_xbrl.py`, 재현 스크립트 `_dg_arelle_probe.py`·`_dg_pipeline_run.py`.

### 6-1. 핵심 결론

singlnote 웹뷰어(8종 한정·소형사 빈응답)와 달리, **XBRL 원본 zip + Arelle 경로는 분식 소형사에서도
비금융 주석(무형자산·차입금·관계기업·리스·충당부채·금융상품)을 실제로 추출·저장할 수 있다.** 표본
10사연도 전수(10/10) 성공. 빈 PASS 아님 — fact 수·주석 카테고리 적중을 수치로 확인.

### 6-2. XBRL zip 가용성 (전수 현황 + 표본 다운로드)

| 항목 | 수치 | 비고 |
|---|--:|---|
| 현재 보유 zip (`raw/financial_statement_xbrl.zip`) | 4 / 4,773 | 삼성 2022~2025뿐(0.08%) |
| 표본 다운로드 시도(분식 소형사) | 10사연도 | finstate_xml API |
| 사업보고서 존재(정정 포함 탐색) | **10 / 10** | 100% |
| zip 다운로드 성공 | **10 / 10** | 179~239KB |
| Arelle 추출 성공 | **10 / 10** | facts 702~1,736 |
| 비금융 주석 fact 저장 | **10 / 10** | 카테고리 적중 74~213 |

핵심: zip이 거의 없는 것은 **수집을 안 했기 때문**이지 데이터가 없어서가 아니다. 표본 10사연도는
전부 다운로드·추출에 성공했다(분모=시도 10).

### 6-3. 보고서 탐색의 함정 (정정·상장폐지) — 근본 수정

기존 `opendart.annual_report()`는 `사업연도+1년` 한 해만 + `final=True`로 본다. 분식 회사는
**사업보고서를 수년 뒤 정정(restatement)으로 다시 제출**하거나 상장폐지로 해당 연도 보고서가 없는
일이 잦아, 좁은 탐색은 가용 데이터를 놓친다(1차 시도에서 8사 중 4사 "사업보고서 없음" 오판).

- 실측: 아스트(00409681) 2018·2019 사업보고서는 **2021-02-05 정정본**으로 제출 → year+1(2020) 창에서 안 보임.
- 신규 `notes_xbrl.find_annual_report()`는 `year+1..year+4` 구간을 훑고 보고서명 `(year.12)` 매칭 중
  **최신(정정) 건**을 고른다 → 동일 표본 재시도에서 10/10 성공.

### 6-5. 전수 수집 옵션·비용 추정 (사용자 결정 §8 — 미실행)

> §1~5의 잠정 권고("singlnote 실익 낮음")는 유지되나, O4는 **실측상 실현 가능**으로 갱신.
