# Claude 홀리스틱 리뷰 — 회사별 FS vs 엔진출력

> 동일 패킷(`review_packets_*.txt`)을 Codex와 독립 리뷰 후 비교(교차검증).
> **상태: 121/121 회사 전수 리뷰 완료.** 발견 유형 5개(S1~S5)로 완전 수렴 —
> 16번째 회사(소프트센) 이후 105개사에서 새 유형 0. 항등식 위반 0/121.

## 최종 수정 목록 (bounded, root-caused)
1. **S1 — canonical 라벨 alias 보강**(config): "당기순이익(손실)", 매출 변종(영업수익·제품매출·방송수익·상품매출), 매출채권/매입채무 조합라벨. 라벨 정규화(괄호·조합 정리) 후 매칭 권장.
2. **S2 — 진행률 계정 canonical 등록 + 사슬 연결**(config): 계약자산·계약부채·미청구공사·초과청구공사·공사손실충당부채. 조선·건설·수주산업 진행률 분식 대응.
3. **S5 — 데이터 sanity 가드**(code): 연도간 스케일 급변(100배+)·비현실 절대값 감지 시 플래그/제외.
- S3(금융·단일연도)=스코프 문서화, S4(극단%)=발굴단계 한계로 LLM 층 몫. (둘 다 버그 아님)
- **계산 정합성은 전수 0 위반 — 숫자는 옳다.**

## 체계적 문제 (전 회사 반복 — 우선순위)

### S1. 🔴 canonical 라벨 alias 불완전 → 흔한 변종이 "기타 중요 계정"으로 강등 (연도별)
- **증상**: 같은 회사의 같은 계정이 연도마다 매핑이 다름. 영업이익은 다 있는데 **당기순이익이 특정 연도 nan**(두산 2017·18, 아스트 2016-18, 디아이동일 2015-18, 셀트리온 2015·16·18, 유네코 2017·18 등 만연).
- **근본원인(검증)**: 라벨 "당기순이익(손실)"이 표준 account_id면 매핑, 비표준(`-표준계정코드 미사용-`, 과거 공시)이면 라벨 alias로 가는데 **alias에 "(손실)" 변종이 없어** 기타로 강등. 디아이동일: 2015-18 "당기순이익(손실)"→기타, 2019 동일라벨→당기순이익.
- **같은 뿌리**: 매출채권/매입채무 조합라벨, 매출(매출액/영업수익)도 동일 패턴.
- **영향**: 관계사슬(영업이익→당기순이익, 순이익→영업CF→운전자본)과 연도별 YoY/z가 강등 연도에 끊김.
- **권고 수정**: 라벨 정규화(괄호 "(손실)/(이익)" 제거, 공백/조합 정리) 후 alias 매칭, 또는 변종 alias 보강. 단 과병합 주의.

### S2. 🔴 미청구공사/계약자산이 canonical에 아예 없음 → 진행률 사슬 불능
- 전 회사 `미청구공사: (canonical 없음)`. 삼성중공업 계약자산 37,839억·계약부채 49,922억, 삼성엔지니어링 단기미청구공사 15,497억·단기초과청구공사 16,876억이 전부 "기타 중요 계정".
- K-IFRS 1115(2018~) 신용어 **계약자산/계약부채**가 canonical에 없음(옛 용어 미청구공사도 없음). → 조선·건설·수주산업의 **진행률 분식 핵심 관계사슬이 작동 불가**(universal 라벨스캔으로만 잡힘).
- 권고: 계약자산/계약부채/미청구공사/초과청구공사 canonical 등록 + 진행률 사슬 연결.

### S3. 🟡 금융업 = 엔진 신호 0 / 단일연도 (스코프 경계, silent)
- KB금융·신한지주·삼성생명: **신호 0개**. 매출·재고·매출채권 없고(상업계정 부재), 핵심자산(대출채권 444조·예수부채·보험계약부채)은 전부 "기타 중요 계정", 패킷상 2023 단일연도만 잡힘.
- 도구는 상업·제조 FS용 — 금융업은 본질적 스코프 밖. 단 **조용히 0을 내지 말고 "금융업: 스코프 외" 명시** 권고.

### S5. 🔴 데이터 sanity check 부재 → 깨진 원천 데이터를 그대로 사용
- **소프트센**: 2022년 자산총계 raw=1.22×10¹⁷(정상의 10⁶배, DART 원천 오류). 2020·21·23은 정상.
  currency 전부 KRW(라벨상 단위차이 아님 — 값 자체가 깨짐).
- **항등식은 성립**(2022 전 계정 동일배율)이라 항등식 체크·Audit B(자산총계 vs raw)가 못 잡음 — raw도
  같은 값이라 일치. → 엔진 신호 전부 쓰레기(매출채권 divergence −63,515,952%, 유형자산 +2.7억% 등).
- 전수 스캔: 인접연도 100배 이상 점프는 **소프트센 1곳뿐**(109중) — 고립적이나, 엔진이 **절대값 sanity
  check 없이** 깨진 데이터를 그대로 신호화하는 robustness 갭. (DART 원천 오류·연도별 단위 불일치 대비)
- 권고: 연도간 스케일 급변(예: 100배+)·비현실 절대값 감지 시 해당 연도 플래그/제외.

### S4. 🟡 극단-% 아티팩트가 상위 점령 (기존 인지 한계)
- 0근처 base 폭발이 강도10 동점으로 상위 점령: 두산 단기투자증권 +31961%, 이트론 매도가능금융자산 +6476%, 본느 무형자산 +5459%, 삼성중공업 비유동확정계약자산 +11691%, 삼성엔지니어링 지분법손실 +6127% 등 거의 전 회사.
- 판별이 아니라 발굴 단계 노이즈 — LLM 층 몫(기존 결론과 일치).

## 결론: "무한 버그"가 아니라 뿌리 하나
- **계산은 완전 정합**(항등식 0위반, 숫자 전수 일치). 깨진 적 없다.
- **진짜 버그는 한 뿌리**: **canonical 매핑 불완전** — (S1) 라벨 변종("(손실)"·매출액·조합), (S2) 계약자산/미청구공사 미등록. 둘 다 config 수정으로 끝나는 **유한·열거 가능**한 문제.
- **스코프**(S3 금융)·**발굴단계 한계**(S4 극단%)는 버그가 아님.
→ 불신의 핵심("끝없이 나온다")이 풀린다: 계산은 증명적으로 옳고, 매핑 갭은 bounded.
