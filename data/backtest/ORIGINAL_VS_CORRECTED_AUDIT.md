# 원본(정정 이전) 재무제표 수집 가능성 조사

> 읽기전용 조사. 수집 파이프라인 미수정. 모든 수치는 실제 OpenDART API 호출 결과이며
> 정정본 추출값은 `finstate_all` 현재값과 교차검증해 파서 정확성을 확인했다.
> 산출물: `_audit_orig_listings.json`(전체 신고 목록), `_audit_orig_vs_corr_values.json`(수치 대조).

## 1. 결론 (요약)

- **원본(정정 이전) 사업보고서의 재무제표는 받을 수 있다.** 경로가 존재하고 3건 모두 실측 성공.
- 핵심 도구는 두 가지다.
  - `list(final=False)` — 한 회사의 **원본+정정 사업보고서 접수번호를 전부 나열**한다.
  - `finstate_xml(rcept_no)` — **접수번호 단위로 XBRL 원본파일**을 내려받는다. `finstate_all`과 달리
    버전(원본/정정)을 지정할 수 있다.
- 한계: `finstate_xml`이 **모든 보고서에 대해 facts를 주지는 않는다.** 일부 구(舊)·소형 보고서는
  빈 XBRL 템플릿(facts 0개)을 반환한다(아스트 FY2019 사례).

## 2. `finstate_all`의 한계 확인

`finstate_all`(=`fnlttSinglAcntAll.json`)은 파라미터가 `corp_code + bsns_year + reprt_code`뿐이라
**버전을 지정할 수 없다.** 정정신고가 올라가면 DART는 그 사업연도의 "현재 최신본"을 반환한다.

실측 — `finstate_all`이 반환한 `rcept_no`(= 최신 정정본):

```
두산에너빌리티 FY2017  ->  rcept 20240327001228  ([기재정정]사업보고서 2017.12, 2024-03-27 신고)
셀트리온       FY2017  ->  rcept 20220512000845  ([기재정정]사업보고서 2017.12, 2022-05-12 신고)
아스트         FY2018  ->  rcept 20210205000367  ([기재정정]사업보고서 2018.12, 2021-02-05 신고)
```

세 건 모두 회계연도 다음해(원래 신고시점)가 아니라 **수년 뒤 정정 접수번호**를 반환한다.
프롬프트의 문제 제기(분식연도 데이터가 정정본으로 나온다)가 사실로 재확인됐다.

## 3. 원본 수집 경로

### 3-1. 원본 접수번호 나열 — `list(final=False)`

`list(corp, start, end, kind='A', final=False)`는 `last_reprt_at='N'`으로 호출돼
**최종본만이 아니라 원본·정정을 모두** 반환한다. `report_nm`의 `[기재정정]` 접두어로 구분한다.

발견한 원본 vs 정정 접수번호:

```
회사            FY      원본 rcept(신고일)            정정(최종) rcept(신고일)
두산에너빌리티  2017    20180330001846 (2018-03-30)   20240327001228 (2024-03-27)
셀트리온        2017    20180402004060 (2018-04-02)   20220512000845 (2022-05-12)
아스트          2018    20190320000749 (2019-03-20)   20210205000367 (2021-02-05)
```

(셀트리온은 2018-07-20, 2022-05-12 두 차례 FY2017 정정이 있었고 최종은 2022-05-12.)

### 3-2. 원본 재무제표 수집 — `finstate_xml(원본 rcept)`

`finstate_xml(rcept_no, save_as)`(=`fnlttXbrl.xml`)는 접수번호 단위로 XBRL zip을 내려준다.
원본 접수번호를 넣으면 **정정 이전 원본 XBRL**을 받는다. zip 안의 `*.xbrl` instance를 파싱해
연결(ConsolidatedMember)·해당 FY·추가차원 없는 fact에서 자산총계·매출·당기순이익을 추출한다.

추출 대상 계정(IFRS 표준 element): `ifrs:Assets`, `ifrs:Revenue`, `ifrs:ProfitLoss`.

> 파서 검증: 정정본 rcept에서 추출한 값이 `finstate_all` 현재 반환값과 3사 모두 **정확히 일치**
> (예: 두산 자산 24,929,774,707,934 / 셀트리온 자산 3,294,095,985,833 / 아스트 자산 395,053,003,556).
> 즉 추출 로직이 DART 공식값과 동일함을 확인했다.

## 4. 원본 vs 정정본 수치 대조 (연결 기준)

단위: 원. 괄호는 조/억 환산. Δ = 정정 − 원본.

### 두산에너빌리티 FY2017 — **차이 있음 (원본이 분식 방향)**

```
계정         원본                    정정                    Δ
자산총계     24,962,318,127,187      24,929,774,707,934      -32,543,419,253   (자산 약 -325억)
매출         14,523,554,475,823      14,518,845,928,726       -4,708,547,097   (매출 약  -47억)
당기순이익     -109,688,010,762        -197,950,236,801      -88,262,226,039   (손실 약 +883억)
```
원본은 순손실 -1,097억, 정정은 -1,980억. **원본이 손실을 약 883억 작게 표시**(이익 과대 방향).

### 셀트리온 FY2017 — **차이 있음 (원본이 분식 방향)**

```
계정         원본                  정정                  Δ
자산총계     3,458,733,133,237     3,294,095,985,833     -164,637,147,404   (자산 약 -1,646억)
매출           949,079,965,214       949,079,965,214                   0   (동일)
당기순이익     400,728,217,868       377,725,080,593      -23,003,137,275   (이익 약  -230억)
```
원본 순이익 4,007억 → 정정 3,777억. **원본이 이익 230억·자산 1,646억 과대 표시**.

### 아스트 FY2018 — **차이 없음 (원본 = 정정)**

```
계정         원본/정정 (동일)
자산총계       395,053,003,556   (약 3,951억)
매출           117,013,393,875   (약 1,170억)
당기순이익        4,440,459,961   (약 44억)
```
아스트 FY2018의 정정(2021-02-05)은 **재무 헤드라인 수치를 바꾸지 않은 기재정정**이다.
세 항목 모두 원본과 정정이 비트 단위로 동일하다. 아스트의 실제 재무 재작성은 다른 사업연도
(2024년에 집중된 FY2020~2022 다수 정정)에 있을 가능성이 크다. **FY2018만 보면 "정정본=원본"이라
분식 데이터 왜곡 우려가 적용되지 않는다.**

## 5. 비용 (API 호출수·파싱)

회사·연도 1건 기준:

- `list` 호출 1회 (페이지네이션 포함, 한 회사 정기공시 목록).
- `finstate_xml` 다운로드 1회 (zip 약 200~400KB). 원본·정정 비교 시 2회.
- XBRL 파싱: instance(.xbrl) 1개를 ElementTree로 1패스. context/fact 수천 개 수준, 초 단위.
- 별도 LLM·외부 의존 없음. Arelle 불요(표준 element명 직접 추출로 충분).

## 6. 한계·주의

- **XBRL 공백**: `finstate_xml`이 빈 instance(facts 0)를 주는 보고서가 있다.
  아스트 FY2019(rcept 20200330004548)는 2016-08-19자 템플릿에 `Assets` fact가 0개였다.
  원본 수집은 "원본 XBRL이 존재하는 경우"에 한해 동작하며, 구·소형 보고서엔 공백이 있다.
- **연결/별도 구분**: 추출은 연결(CFS) 기준. 연결이 없는 회사는 별도(OFS)로 받아야 한다
  (아스트는 연결·별도 모두 존재).
- **정정 다단계**: 한 사업연도에 정정이 여러 번일 수 있다(셀트리온 FY2017 2회). 원본은
  `[기재정정]`이 없고 신고일이 가장 이른 건이다.

## 7. 백테스트 검증에의 함의

- 두산·셀트리온은 `finstate_all`이 정정본(분식 수정 후)을 주므로, **분식탐지 검증에는 원본 XBRL을
  별도 수집해 써야 의미가 있다.** 원본 수집 경로(§3)가 이를 가능케 한다.
- 아스트 FY2018은 원본=정정이라 어느 쪽을 써도 동일 — 이 회사·연도는 "정정본 오염" 문제에서
  제외해도 된다. (단일 케이스로 일반화 금지: 회사·연도마다 원본/정정 동일 여부를 확인할 것.)
