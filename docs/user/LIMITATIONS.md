# 프로젝트 한계 (Known Limitations)

이 도구가 다루지 못하거나 사용 시 주의해야 할 점을 한곳에 정리한다. 입사용/검토용 프로젝트로서
"무엇을 못 하는지"를 숨기지 않고 명시하는 것이 신뢰의 전제다. 세부 근거는 각 항목의 링크 문서를 참조한다.

## 1. 외화재무(비원화) 회사는 분석에서 제외된다

DART에 재무제표를 USD 등 외화로 신고한 회사가 있다(로컬 corpus 기준 약 39개 회사연도, 전 표가 외화).
이 도구는 모든 금액을 원(KRW)으로 가정해 계산하므로, 외화 금액을 그대로 쓰면 환율(약 1,300배) 만큼
규모가 틀어진다. 더 위험한 점은 자산=부채+자본 같은 항등식은 같은 외화 단위라 깨지지 않아, 이 오차가
검산에 잡히지 않고 조용히 통과한다는 것이다.

- **대응**: 온보딩 게이트가 통화 단일성을 검사해, 비원화(외화) 재무 회사는 "원화 분석 부적합"으로
  **차단**한다(분석 진입 불가). 조용히 1,300배 틀린 결과를 내느니 명시적으로 제외한다.
- **미지원**: 환율 환산은 하지 않는다. DART가 환율을 제공하지 않고, 회계상 자산은 기말환율·손익은
  평균환율로 시점이 달라 임의 환산이 오히려 더 부정확하기 때문이다.

## 2. 신규 회사 온보딩은 LLM에 의존한다

신규 회사를 분석에 넣으려면 온보딩 단계에서 LLM 통독 2종(계정 별칭 제안 · Layer 1 서술 리더의 파트별
읽기)이 실행돼야 한다. 게이트(G1~G5)는 결정론이라 무료다.

- **비용**: 회사당 약 ₩300~800, 소요 2~5분(대부분 서술 리더의 본문 통독). 대형 금융사는 본문이 30만
  토큰을 넘어 비용·시간이 더 든다. 운영 전수(수천 사)는 비용상 수행하지 않는다.
- **실패 시**: API 키 미설정이나 호출 실패 때 분석을 영구 차단하지 않는다. "본문 위험 미추출" 등
  경고를 띄우고 사람이 확인 후 진행한다(silent 누락은 막되, 장애로 멈추지는 않게).
- **별칭 등록은 고신뢰만 자동**: 신뢰도 0.7 이상 제안만 자동 등록·재정규화하고, 미만·후보없음은
  보류한다. 보류 계정은 사라지지 않고 '기타 중요 계정'으로 분석에 남으며, 자산 5% 이상이면
  표준분류 못한 큰 계정 카드로 감사인에게 표면화된다. 자동 등록분은 quirk에 auto 표기로 남아
  전처리 페이지에서 교정·해제할 수 있다.

## 3. 서술형 감사관심사항은 Layer 1 서술 리더를 실행해야 전달된다

소송·특수관계자 거래·우발채무 같은 "글로 쓰인 위험"은 정형 주석(XBRL)이 아니라 사업보고서 본문에 있다.
Layer 1 서술 리더가 본문을 파트별로 읽어 추출(report_extracts)해야 이 정보가 Layer 2 분석에 전달된다.
미실행 시에는 빈 채로 두지 않고 "서술 추출 미실행 — 본문 위험 누락 가능" 경고를 분석 입력에 명시한다.
리더가 실행돼도 놓친 항목은 완결성 3중 결정론 앵커(섹션·가나다·물질금액 커버리지)가 "이 섹션 0추출" 식으로
경고해 조용한 누락을 막는다(설계 §7).

## 4. 게이트(검문)가 보장하는 범위에는 경계가 있다

온보딩 게이트는 정규화 품질을 검문해 불완전한 데이터의 분석 진입을 막는다. 빈/부분 데이터, 재무상태표(BS)
결손, 자본변동표(SCE) 표준화 실패, 외화재무는 차단한다. 다만 다음은 현재 한계다.

- **단일 회사 범위**: 게이트는 한 회사연도만 본다. 여러 회사에 걸친 계정 매핑 충돌(G2)은 보고만 하고
  통과 판정에는 넣지 않는다.
- **수집 실패 표기 미완**: 재무 수집이 네트워크 오류로 실패하면 빈 데이터가 될 수 있다. 게이트의
  데이터 검증(BS 검산 등)이 빈 데이터를 차단하므로 잘못된 분석으로 이어지지는 않지만, "수집 실패"를
  별도로 명시 기록하는 기능은 아직 없다.
- 상세: [P1_AUDIT_HARNESS.md](../agent/P1_AUDIT_HARNESS.md)(본질적 한계), [BACKTEST_ANALYSIS.md](BACKTEST_ANALYSIS.md)(도구 약점).

## 5. 이 도구는 부정(분식)을 확정하지 않는다

산출물은 "감사인이 검토할 리스크 후보"이지 분식 확정·자동 적발·성능 보장이 아니다. 모든 발견은
반대 근거·정상 설명·확인 질문·다음 절차를 함께 제시한다. 도구가 무엇을 잡고 무엇을 왜 놓치는지는
[BACKTEST.md](BACKTEST.md)·[BACKTEST_ANALYSIS.md](BACKTEST_ANALYSIS.md)에서 실제 분식 사건으로 검증한다.

## 6. Phase2 멀티에이전트 실호출은 비용·시간이 든다

6관점 병렬 검토 → 코드 클러스터·점수 → 반박 에이전트 → 의심건 카드까지 결정론 골격과 배선은
코드로 완성·단위테스트 고정돼 있고, 실제 LLM 호출 전과정 E2E(수집→정규화→온보딩→Phase1→Phase2)를
1개사(대주산업 00112457/2024, 소형 비금융)에 측정했다.

- **소형사 1회 약 ₩1,365·158초, 병목은 Phase2**(비용 72%·시간 59%). 금융사·대기업은 본문·계정이
  커서 크게 는다. 운영 전수(수천 사)는 비용상 수행하지 않는다.
- 단계별 실측표·정확성 before→after·비결정성은 [VERIFICATION.md](VERIFICATION.md)의 "전과정 E2E
  평가(대주산업)" 참조. 설계 단일출처: [../agent/PHASE2_DESIGN.md](../agent/PHASE2_DESIGN.md).

## 8. 주석 숫자표의 연도별 신규/소멸 추적은 미지원

"올해 새로 생긴 항목·작년에 있다 사라진 항목"을 자동 표시하는 기능은 **계정·자본변동(SCE)·서술형
공시(담보·소송)에는 적용되지만, 정형 주석(XBRL) 숫자표에는 적용하지 않는다.** 주석 XBRL은 항목의
분류 체계가 매년 바뀌어(예: 금융자산 분류축이 해마다 재편) 같은 항목을 연도 간에 안정적으로 맞출 수
없기 때문이다. 실측상 단순 대조하면 신규가 34~64%로 부풀려져 신뢰할 수 없다. 주석 숫자표 자체는
분석에 전량 포함·근거검증(grounding)되므로 누락은 아니며, "신규/소멸" 딱지만 붙지 않는다. 이 추적이
실제로 필요해지면 주석 표준화 사전(온톨로지)을 도입해 처리할 예정이다.
