# 멀티에이전트 — 관점들이 어떻게 일하나

> 이 도구의 심장은 *"여러 AI가 각자 다른 각도로 회사를 보고, 결과를 맞대 교차검증하는 것"*이다.
> 각 관점의 **기능 / 작동 / 왜 그렇게 했는지**를 정리한다. 누구에게든 이 문서로 설명할 수 있다.
> 설계 근거 원문은 [../agent/DECISION.md](../agent/DECISION.md), [../agent/PLAN.md](../agent/PLAN.md).

## 왜 "멀티에이전트"인가

한 AI가 회사를 다 보면 **한 관점에 매몰**된다. 여러 관점이 **서로의 답을 안 보고 독립적으로**
평가한 뒤 부딪혀야, *"숫자는 위험한데 주석은 잠잠하다 → 더 의심스럽다"* 같은 **충돌**을
잡아낼 수 있다. 이게 단일 LLM 요약과의 결정적 차이다. (근거: DECISION D9)

```
6개 관점이 독립 평가  →  코드가 계정별로 묶고 점수 매김  →  반박 에이전트가 반대근거 채움  →  의심건 카드 목록
   (서로 안 봄)          (같은 계정 = 한 카드, 표수 N/4)      (정상이유·확인질문·다음절차)        (계정 카드 + 회사레벨 카드)
```

- **일치(agreement)** = 여러 관점이 같은 계정을 가리킴 → 그 카드 표수(N/4)가 올라감 → 신호 강화
- **충돌(conflict)** = 한쪽은 위험인데 다른 쪽은 잠잠 → "회사 고유 가능성"으로 주목
- 최종 산출물은 "한 단락 종합"이 아니라 **의심건별 카드 목록**이다. 묶기·점수·확신도는 코드가
  결정론으로 하고(원칙①), 카드마다 전용 **반박 에이전트**가 정상 설명·확인 질문을 채운다.

## 관점 6개

### ① 수치 (numeric)
- **기능**: 재무 지표·증감률을 보고 정량 리스크를 판단 (예: 매출채권 +17%, DSO 51일)
- **작동**: L2 결정론 코드가 계산한 신호·지표를 받아 **해석만** 한다 (계산은 안 함)
- **왜**: "정량 × 수준" 차원. 숫자의 이상을 보는 가장 기본 관점. **당해 급변(전년比 튐)은 수치
  관점 전담**이라, 다년 방향은 추세 관점에 맡긴다.
- **모델**: GPT-5.4 (reasoning)

### ② 주석 (note)
- **기능**: 회사가 쓴 주석에서 정성 리스크 (대손충당금·재고평가손실·신용위험 등)
- **작동**: 주석 인덱서가 계정에 매핑한 주석 섹션을 받아, 실제 쓰인 문구만 인용
- **왜**: "정성 × 수준". *숫자 vs 글*을 대조하는 교차검증의 핵심
- **모델**: GPT-5.4 (reasoning)

### ③ 흐름 (flow)
- **기능**: 재무제표 **간** 정합 (이익↔현금흐름, 매출↔매출채권↔영업CF 사슬)
- **작동**: BS-IS-CF 관계 신호를 받아, 아귀가 맞는지 해석
- **출력**: 관계 모순은 단일 계정이 아니라 **"관계 카드"(relationship)**로 낸다 — 엮인 계정을 함께
  묶어 표시한다. 연결↔별도 현금 괴리 같은 재무제표 교차도 관계 카드로 낸다.
- **왜**: "공간 교차". *"이익은 났는데 현금흐름은?"* 같은 모순을 잡음. 단일 계정 급변은 수치·추세
  관점 소관이라, 관계가 아니면 중복 제출하지 않는다.
- **모델**: GPT-5.4 (reasoning)

### ④ 추세 (trend)
- **기능**: 여러 해에 걸친 **방향성** (매출채권 3년째 증가, 관계기업투자 완만 감소 등)
- **작동**: 다년 기울기를 받아 점점 증가/감소하거나 완만히 드리프트·가속하는 계정을 해석
- **왜**: "시간 교차". 한 해에 튄 것(당해 급변)은 **수치 관점 전담**이라 보지 않는다. 추세는
  당해 급변이 못 잡는 다년 방향만 전담해 수치 관점과 겹치지 않게 한다.
- **모델**: GPT-5.4 (reasoning)

### ⑤ 외부 (external)
- **기능**: 내부에서 튄 이상의 **"원인"을 뉴스에서 찾기** (예: 차입금 급증 → "M&A 실탄?")
- **작동**: 내부 신호 → AI가 **원인을 찾는 검색어를 스스로 생성**(매핑 없음) → 구글 검색 →
  **출처가 확인된 결과만** 보고 평가
- **왜**: ISA 520 분석적 절차의 외부 정보 비교. **단, 외부는 "설명"이지 "면죄부"가 아니다** —
  업황 탓이라며 내부 위험을 지우지 않는다. 못 찾으면 "회사 고유"로 표시 (D8·D11·D13·D14)
- **모델**: GPT-5.4 (reasoning). 관점 해석은 6관점 모두 GPT-5.4로 통일했다. 단 외부 근거
  수집(검색·출처 확보)은 해석과 분리된 별도 단계다.

### ⑥ 동종업계 (peer)
- **기능**: 업종 평균 대비 이 회사가 어디 서 있나 (분위 위치·이탈)
- **작동**: 같은 업종 피어(DART 업종코드 자동)의 **지표만** 수집(주석·풀분석 안 함) →
  업종 분위수 → 우리 회사 위치 비교. (예: 삼성 DSO 업종 분위 100 = 회수기간 최장 → 매출채권
  신호 강화)
- **왜**: ISA 520 industry comparison. 외부처럼 참고 관점(판단 비오염). 단 회사별 사업구조
  차이(사과-오렌지) 때문에 "참고 신호"로만 (PLAN §16.1, D15)
- **모델**: GPT-5.4 (reasoning)

## 반박 에이전트 (6관점과 별개)

6관점이 의심건을 내고 코드가 카드로 묶은 뒤, **전용 반박 에이전트 1명**이 카드 전체를 일괄
1회 받아 카드마다 반대근거를 채운다. 6관점은 "무엇이 이상한가"를 보고, 반박은 "정상으로
설명될 가능성은 없나"를 따지는 별도 역할이다. (설계: [../agent/PHASE2_DESIGN.md §10](../agent/PHASE2_DESIGN.md))

반박이 채우는 칸:
- **정상 설명**(normal_explanation) — 정상 사업 활동으로 설명 가능한 시나리오
- **반대 근거**(counter_evidence) — 숫자·구조상 의심에 반대되는 근거
- **확인 질문**(confirm_question) — 감사인이 회사에 던질 질문
- **다음 절차**(next_procedure) — 제안하는 다음 감사 절차
- **반박 판정**(verdict) — 정상우세 / 반반 / 의심우세

반박의 권한은 제한된다(은폐 방지, CLAUDE.md §9):
- 카드를 **삭제하지 못한다.** 판정 플래그만 붙인다("정상우세"면 목록 하단으로 강등 표시).
- 위험도 숫자를 직접 바꾸지 못한다(점수는 코드 산정).
- 반박이 실패·누락된 카드는 "반박 미수행"으로 명시하고 그대로 노출한다(빈칸 숨김 금지).
- **모델**: GPT-5.4 (reasoning)

> 과거 설계에선 반박을 "6관점 교차가 곧 반박"이라며 뺐으나, 카드마다 정상 설명·확인 질문을
> 책임지고 채울 주체가 필요해 전용 에이전트로 되살렸다.

## 공통 안전장치 (환각 방어)

모든 관점에 적용:
- **계산은 코드, 해석만 LLM** — 숫자를 AI가 지어내지 못함
- **근거 필수** — 모든 주장은 실제 수치·주석 위치(EvidenceRef)를 인용
- **외부 사실 단정 금지** — "반도체 불황이었다" 같은 걸 기억으로 단정 안 함 (외부는 검색+출처만)
- **확정 회피** — "분식이다"가 아니라 "검토 후보 + 정상일 수 있는 이유 + 확인 질문"

## 데이터 흐름 (한눈에)

```
   ┌────────────────────────────────────────────────────┐
   │  회사 재무제표 5장 · 전 계정                          │
   │  재무상태표 · 손익 · 포괄손익 · 현금흐름 · 자본변동     │
   └────────────────────────────────────────────────────┘
                          │
                          │  ① 숫자 규칙(결정론)이 5장을 통째로 읽음
                          ▼
   ┌────────────────────────────────────────────────────┐
   │  전 계정 계산값(전부, 등수 없음)  +  관계신호           │
   │  +  재무비율  +  주석                                 │
   └────────────────────────────────────────────────────┘
                          │
                          │  ② 관점별로 필요한 종류만 나눠줌(순위·선별 없이 전부)
                          ▼
   ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐
   │ 수치 │ │ 흐름 │ │ 변동 │ │ 주석 │ │ 외부 │ │ 동종 │   ③ 6개 AI
   └──────┘ └──────┘ └──────┘ └──────┘ └──────┘ └──────┘     각자 독립 판단
                          │
                          ▼
        교차검증(코드가 같은 계정끼리 묶고 표수·점수 산정)
                          │
                          ▼
                반박 에이전트(정상이유·확인질문 채움)
                          │
                          ▼
              ┌────────────────────────────┐
              │  의심건 카드 목록             │
              │  (계정 카드 + 회사레벨 카드)   │
              │  ※ 확정 아님 — 사람이 최종 확인 │
              └────────────────────────────┘
```

- **5장을 통째로 읽는 건 '숫자 규칙'(결정론)**이다. 그 산출물은 **추려진 후보 목록이 아니라
  전 계정 계산값 전부(증감률·추세·변동성·구성비·z·관계신호)**다. AI는 이 전부를 받아 **무엇이
  유의한지 스스로 고른다.** 코드가 "이게 수상하다"고 등수를 매겨 건네지 않는다(추론은 관점 AI의 몫).
  - 과거엔 코드가 추린 "수상한 후보 목록(등수 힌트)"을 함께 줬으나, 그 목록 밖(예: 막 급증한
    설비투자)을 AI가 덜 보게 만드는 주의 편향이 있어 제거했다. 계산값은 그대로 전부 전달된다.
- **묶기·표수(N/4)·금액유의성·이상도·확신도는 코드가 결정론으로 산정**한다(AI는 점수를 매기지 않는다).
- 의심건이 0건이면 빈 화면 대신 **"계정 N개·관점 6개 검토, 의심건 0"**으로 검토 범위를 명시한다.
- **점수는 안정적인 재무상태표·손익만 매긴다.** 현금흐름·포괄손익처럼 원래 많이 출렁이는 건 점수 대신
  **AI가 맥락으로 판단**한다(정상 변동인지 분식인지). 그래서 멀쩡한 회사를 분식으로 오해하지 않는다.
- AI는 의심 근거·반대 근거·확인 질문을 내놓되 **확정하지 않는다 — 최종 판단은 사람(감사인)**이다.
