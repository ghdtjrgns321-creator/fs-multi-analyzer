# UX — 사용자 경험 흐름 (설계안)

> ⚠️ 현재 구현 전이다. 아래는 **계획된 흐름·원칙**이며, 구현하면서 갱신한다.
> 기반: [../agent/PLAN.md](../agent/PLAN.md)(L5 Human·포지셔닝).

## 누가 쓰나

회계감사인 · 재무분석가. 회사 재무제표를 빠르게 리스크 스크리닝하고, 검토 우선순위를
정하려는 사람.

## 사용 흐름 (계획)

```
회사 선택
  → (자동) 수집 → 정규화 → 온보딩(게이트·청크선별·별칭·통독, 필수)
  → 6관점 독립 분석 → 코드 클러스터·점수 → 반박 에이전트
  → 리포트 열람 (의심건 카드 목록, 표수·유의성 순)
  → 카드별 근거 확인 (숫자·주석 원문 추적)
  → 승인 / 기각 / 추가 질문
  → (다음 감사 절차 메모)
```

사용자는 숫자를 직접 계산하거나 주석을 일일이 뒤지지 않는다. 도구가 후보를 올리고,
사용자는 **판단과 결정**에 집중한다.

## UX 원칙 (PLAN 계승)

| 원칙              | 의미                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| Human-in-the-Loop | AI가 확정하지 않는다. 사람이 최종 판단한다                             |
| 근거 우선         | 모든 지적은 클릭 한 번으로 숫자·주석 원문까지 추적 가능                |
| 확정 회피         | "분식"이라 단정하지 않고 "검토 후보 + 정상일 수 있는 이유"를 함께 제시 |
| 설명 가능         | 어느 에이전트가 왜 그렇게 판단했는지 과정을 노출                       |

## 왜 이런 UX인가

감사에서 가장 위험한 것은 **실재하는 문제를 놓치는 것**(2종오류)이다. 그래서 도구는
확정해서 사람을 안심시키기보다, **검토할 후보를 근거와 함께 넓게 올려** 사람이 판단하도록
돕는다. AI의 과잉 확신을 구조적으로 막는 것이 이 UX의 핵심이다.

## 구현해야 할 핵심 인터랙션 (메모)

### 계정 사전 자동 보강 (Human-in-the-Loop)

정규화에서 표준 코드·한글 이름으로 **못 맞춘 계정**은 "못 맞춘 칸" 목록으로 화면에 뜬다.
사용자가 "이건 ○○ 계정이다"라고 지정하면 사전(`config/canonical_accounts.yaml`)에 한 줄
추가되고, 다음부터 자동 매칭된다.

- 사전을 미리 다 채우지 않고, 쓰면서 한 줄씩 키우는 방식(점진적 확장).
- 표준 코드가 1차로 대부분 잡고, 이 보강은 빠진 소수만 메운다.
- **UI/UX 구현 단계(L5)에서 반드시 포함할 것.**
