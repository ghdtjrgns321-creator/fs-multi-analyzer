# UI·UX — 화면 구성과 사용자 흐름

> 대시보드(`dashboard/app.py`, 첫 화면 = 분석 리포트)의 사용자 흐름·화면·UX 원칙을 한 문서로.
> ⚠️ 첫 화면 직행·실시간 검색·게이트·카드 산출은 구현됐고, **분석 준비 버튼·Phase2 gating 등
> 일부 배선은 미완**이다(§구현 상태). 기반: [../agent/PHASE2_DESIGN.md §3](../agent/PHASE2_DESIGN.md)(카드 구조)·
> [../agent/PLAN.md](../agent/PLAN.md)(L5 Human·포지셔닝).

## 누가 쓰나

회계감사인 · 재무분석가. 회사 재무제표를 빠르게 리스크 스크리닝하고, 검토 우선순위를
정하려는 사람. 사용자는 숫자를 직접 계산하거나 주석을 일일이 뒤지지 않는다. 도구가 후보를
올리고, 사용자는 **판단과 결정**에 집중한다.

## 한눈에 — 전체 흐름

```
┌──────────────────────────────────────────────────────────────────┐
│  FS Multi-agents analyzer — 분석 워크플로우                        │
└──────────────────────────────────────────────────────────────────┘

 [1] 회사 검색  (실시간 typeahead)
       │  "삼성" 입력 → 등록회사 즉시 드롭다운(상장사 우선)
       ▼
 [2] 회사·연도 선택
       │  배지: raw 보유연도 [2020–2025] · 준비완료 [2024,2025]
       │  연차(사업연도) FS만 지원 · 수집 윈도우 = 타깃 + 직전 4년 = 5년
       ▼
 [3] 분석 준비   ← 버튼 (자동·무료, ~15초/회사)
       │  ├ (raw 없으면) 수집        collect_company_years    [DART 호출]
       │  ├ 재정규화                normalize_company_years  [raw→DB, 최신코드]
       │  ├ 주석 숫자 분류          load_notes_classified
       │  └ 온보딩 게이트 G1~G5     run_gate  (품질 검문)
       │        PASS ─┐         FAIL ─→ quirk 교정 → 재게이트
       ▼             │
 [4] Phase1 결정론 리포트   ← 게이트 PASS 후 활성 (무료, ~5초)
       │  검토 우선순위 큐 · 비율 요약 · 계정 시계열
       ▼
 [5] Layer 1 서술 리더   ← 별도 버튼 (비용, 본문 통독) · 설계확정·구현예정(Plan B)
       │  본문 다운로드 · PART 분해 · 파트별 리더가 읽어 핵심 추출(report_extracts) · 완결성 앵커 경고
       │  별칭 제안 → 고신뢰(≥0.7)만 자동 등록·재정규화, 저신뢰·기타는 보류(감사인 확인 UI 없음)
       │  → 서술형 공시(우발·소송·특수관계) 추출물을 Layer 2에 공급
       ▼
 [6] Layer 2 의심건 카드   ← 마지막, Phase1 뜬 뒤에만 노출 (LLM·비용, ~90초)
       기존 Phase2 6관점 병렬 → 근거검증 → 클러스터·점수 → 반박
```

## 회사 상태 3분류 (선택 시 자동 판정)

회사마다 저장 상태가 달라 흐름이 갈린다. raw(원본)·DB 존재로 판정한다.

```
상태 A  미수집          raw 없음                 → [분석 준비]가 수집(DART)부터
상태 B  수집됨·미준비    raw 있음 / 준비 안 됨     → [분석 준비]가 재정규화+게이트만 (DART 불필요)
상태 C  준비완료        게이트 PASS·최신 DB       → 바로 Phase1
```

## 의심건 카드 (메인 화면의 한 항목)

각 카드는 다음을 한 항목에 담는다 (스키마: AccountFinding + 카드 메타, PHASE2_DESIGN §3):

```
[계정] 매출채권        표수: 3/4   우선순위 점수: 0.82   유의성: 0.8   확신도: Med
참고배지: 외부·동종     반박 판정: 의심우세
─────────────────────────────────────────────
조사 결론 : 원인 경로·좁혀진 지점·이상 지점·남은 확인사항 (조사원, 카드 최상단)
숫자 근거 : 매출 +12% / 매출채권 +58% / DSO 41→67일
주석 근거 : 주요 고객 신용위험 집중도 증가
흐름 근거 : 영업현금흐름 감소
정상 설명 : 신규 대형계약 일시 증가 가능성 (반박 에이전트)
확인 질문 : 거래처별 매출채권 연령분석표상 회수 지연 여부
다음 절차 : 거래처별 매출채권 연령분석표 입수
```

- **표수(N/4)**: 내부 4관점(재무 수치·주석·계정 간 관계·시계열 추세) 중 몇 명이 이 계정을 지적했나. 외부 근거·업종 비교는 참고배지.
- **반박 판정**: 정상우세 / 반반 / 의심우세 (정상우세 카드는 목록 하단으로 강등 표시).
- **회사레벨 카드**(계정 앵커 없는 외부·소송·지배구조 등)는 별도 섹션에 표시.
- 표수·유의성·이상도·확신도·우선순위 점수는 코드가 결정론으로 산정한다(AI는 점수를 매기지 않음,
  High/Medium/Low 라벨은 폐지).

## 확정 결정

| #   | 항목                | 결정                                         | 이유                                       |
| --- | ------------------- | -------------------------------------------- | ------------------------------------------ |
| 1   | 첫 화면             | 탭 없이 분석 리포트 직행                     | 온보딩·개요 탭 제거, 검색이 진입점         |
| 2   | 회사 검색           | 실시간 typeahead(streamlit-searchbox)        | 타이핑마다 등록회사 드롭다운, 상장사 우선  |
| 3   | 수집 연수           | 5년(타깃 + 직전 4년)                         | YoY·추세 신호에 필요, 코드 윈도우와 정합   |
| 4   | 낡은 정규화 DB      | A안 — 준비 때 재정규화(wipe 없음)            | raw 보존, 낡은 27%만 준비 시 덮어씀, 멱등  |
| 5   | 분석 준비 범위      | 수집·재정규화·주석분류·게이트까지 자동(무료) | 게이트는 비용 없음, 준비 한 번에           |
| 6   | Layer 1 서술 리더   | 별도 버튼으로 분리                           | 본문 통독은 비용 발생 → 사용자가 명시 실행 |
| 7   | Phase1              | 게이트 PASS 후 활성                          | 온보딩 안 거친 분석 차단                   |
| 8   | Phase2(의심건 카드) | 마지막 단계, Phase1 뜬 뒤에만 노출           | LLM 비용 큰 최종 단계, 초기 숨김           |
| 9   | 저장 연도 표시      | 회사 선택 시 raw·준비완료 연도 배지          | 무엇이 준비됐는지 사용자가 인지            |

## 파생물 3종 — 무엇이 어디서 만들어지나

```
raw (보존)                          →  파생물(재생성 가능)
─────────────────────────────────     ──────────────────────────────────
finstate_all_CFS/OFS.csv, XBRL zip  →  normalized_financials  (재정규화)
  "                                 →  sce_equity_components   (재정규화)
notes_xbrl/note_facts.tsv           →  note_facts_classified   (주석 숫자 분류)
사업보고서 본문(리더 실행 때 다운로드) →  report_extracts(DuckDB, 회사/연도 격리)
```

- 재정규화 = raw에서 파생물만 최신 코드로 다시 생성. DART 재호출 없음(1개사 5년 ≈ 15초).
- 서술형 본문 추출(Layer 1 리더)은 정규화가 아니라 **별도 리더 단계**에서 붙어 report_extracts에 캐시된다.

## UX 원칙 (PLAN 계승)

| 원칙              | 의미                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| Human-in-the-Loop | AI가 확정하지 않는다. 사람이 최종 판단한다                             |
| 근거 우선         | 모든 지적은 클릭 한 번으로 숫자·주석 원문까지 추적 가능                |
| 확정 회피         | "분식"이라 단정하지 않고 "검토 후보 + 정상일 수 있는 이유"를 함께 제시 |
| 설명 가능         | 어느 에이전트가 왜 그렇게 판단했는지 과정을 노출                       |

**왜 이런 UX인가**: 감사에서 가장 위험한 것은 **실재하는 문제를 놓치는 것**(2종오류)이다.
그래서 도구는 확정해서 사람을 안심시키기보다, **검토할 후보를 근거와 함께 넓게 올려** 사람이
판단하도록 돕는다. AI의 과잉 확신을 구조적으로 막는 것이 이 UX의 핵심이다.

## 차별 요소

- **교차검증 과정 펼쳐보기**: 어느 에이전트가 무엇을 주장하고 반박 에이전트가 어떻게
  검증했는지 토론 로그를 열어볼 수 있게 한다(설명 가능성).
- **근거 추적**: 숫자·주석 근거를 클릭하면 원문 위치로 이동(EvidenceRef 기반).

## 계정 이름 자동 보정 (온보딩 내장)

정규화에서 표준 코드로 **못 맞춘 계정**은 온보딩 때 LLM이 표준 이름 후보로 분류하고,
확실한 것만 자동 등록한다. 감사인 화면에는 이 과정이 보이지 않는다(전처리 운영 작업이라
감사 판단 흐름에서 분리).

- **자동 등록**: 신뢰도 0.7 이상·후보 목록 안 제안만 회사별 사전(`config/company_quirks.yaml`)에
  등록하고, 분석 윈도우 5개년을 즉시 재정규화해 이번 분석부터 반영한다. 등록분은 `auto` 표기로
  남아 수동 등록과 구분된다(감사추적).
- **보류**: 신뢰도 미만·적절한 후보 없음은 등록하지 않는다. 보류 계정은 사라지지 않고
  '기타 중요 계정'으로 분석에 남으며, 자산 5% 이상이면 "표준분류 못한 큰 계정" 카드로
  감사인에게 표면화된다.
- **수동 교정**: 틀린 자동 등록의 해제·보류분 수동 등록은 전처리 페이지
  (`dashboard/onboarding.py` 별도 실행)에서 한다.
- 사전을 미리 다 채우지 않고, 회사를 온보딩하면서 한 줄씩 키우는 방식(점진적 확장).
  표준 코드가 1차로 대부분 잡고, 이 보정은 빠진 소수만 메운다.

## 구현 상태

| 상태 | 항목                                                                                                                                                  |
| ---- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| 완료 | 첫 화면 직행 · 실시간 검색 · 연도 드롭박스 · 연차FS 안내 · 좌우폭 축소                                                                                |
| 예정 | [분석 준비] 버튼·파이프라인 배선 · 3상태 배지 · 게이트 결과 표시 · Layer 1 서술 리더 별도 버튼 · Layer 2 gating · 수집/분석 윈도우 5년 반영(현재 4년) |

> 비용 주의: Layer 2(Phase2)·Layer 1 서술 리더는 LLM 호출 비용이 발생한다. 소형사 기준 리더 수백 원,
> Layer 2 약 1,000~1,900원(회사 규모에 따라 상이). Phase1·분석 준비(게이트)는 무료.
