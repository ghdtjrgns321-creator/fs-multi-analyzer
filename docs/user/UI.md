# UI — 화면 구성 (설계안)

> ⚠️ 카드 산출(markdown 렌더)·온보딩 게이트는 코드로 구현됐고, **메인 리포트 화면의 Streamlit
> 배선은 아직 미완**이다. 아래는 카드 구조에 맞춘 화면 설계이며 배선하면서 갱신한다.
> 기반: [../agent/PHASE2_DESIGN.md §3](../agent/PHASE2_DESIGN.md)(카드 구조)·[../agent/PLAN.md §5](../agent/PLAN.md)·L5 Human, 기존 프로젝트의 Streamlit 자산.

## 기술

Streamlit + plotly. 파이썬 단일 코드로 회사·연도 선택 → 분석 → 리포트 열람.

## 화면 구성 (계획)

| 화면              | 내용                                                                                     |
| ----------------- | ---------------------------------------------------------------------------------------- |
| 1. 회사·연도 선택 | DART에서 회사 검색, 분석 대상 3개년 지정                                                 |
| 2. 온보딩(필수)   | 게이트 → 본문 청크선별(S7) → 별칭 제안 → 통독(G6)을 한 버튼으로 실행, 통과해야 분석 진입 |
| 3. 분석 진행      | 6관점(수치·주석·흐름·추세·외부·동종업계) + 반박 에이전트의 작업 상태 표시                |
| 4. 리포트 (메인)  | 의심건 카드 목록 — 계정 카드 + 회사레벨 카드를 표수·유의성 순으로 정렬                   |
| 5. Human 검토     | 카드별 승인 / 기각 / 추가 질문                                                           |

## 의심건 카드 (메인 화면의 한 항목)

각 카드는 다음을 한 항목에 담는다 (스키마: AccountFinding + 카드 메타, PHASE2_DESIGN §3):

```
[계정] 매출채권        표수: 3/4   위험도: High   유의성: 0.8   확신도: Med
참고배지: 외부·동종     반박 판정: 의심우세
─────────────────────────────────────────────
숫자 근거 : 매출 +12% / 매출채권 +58% / DSO 41→67일
주석 근거 : 주요 고객 신용위험 집중도 증가
흐름 근거 : 영업현금흐름 감소
정상 설명 : 신규 대형계약 일시 증가 가능성 (반박 에이전트)
확인 질문 : 거래처별 매출채권 연령분석표상 회수 지연 여부
다음 절차 : 거래처별 매출채권 연령분석표 입수
```

- **표수(N/4)**: 내부 4관점(수치·주석·흐름·추세) 중 몇 명이 이 계정을 지적했나. 외부·동종은 참고배지.
- **반박 판정**: 정상우세 / 반반 / 의심우세 (정상우세 카드는 목록 하단으로 강등 표시).
- **회사레벨 카드**(계정 앵커 없는 외부·소송·지배구조 등)는 별도 섹션에 표시.
- 표수·유의성·이상도·확신도는 코드가 결정론으로 산정한다(AI는 점수를 매기지 않음).

## 차별 요소 (계획)

- **교차검증 과정 펼쳐보기**: 어느 에이전트가 무엇을 주장하고 반박 에이전트가 어떻게
  검증했는지 토론 로그를 열어볼 수 있게 한다(설명 가능성).
- **근거 추적**: 숫자·주석 근거를 클릭하면 원문 위치로 이동(EvidenceRef 기반).
