# 엔진 검증 — 전수 홀리스틱 리뷰로 신뢰를 세운 방법

> 분식을 잡는 도구라면, 도구 자체가 *맞게 계산하는가*를 먼저 믿을 수 있어야 한다.
> 이 문서는 신호 엔진의 정확성을 어떻게 검증했는지(방법)와 무엇이 나왔는지(결과)를 정리한다.
> 검증 산출물: `data/backtest/REVIEW_CLAUDE.md`·`REVIEW_CODEX.md`·`FIX_LIST.md`.

## 왜 — "찔러보기식 검증"의 한계

버그를 하나씩 찾는 방식에는 근본 결함이 있다.
- 미리 정의한 것만 검사한다. 정의하지 않은 종류는 못 잡는다.
- **수렴 신호가 없다.** "이제 버그 없다"를 증명할 방법이 없으니, 새 버그가 나올 때마다 신뢰가 깎인다.

그래서 검증 방식을 바꿨다. *기계적 불변식 점검*(정의한 것만 봄)이 아니라, **LLM이 회사 하나하나의
재무제표 전체를 직접 읽고 엔진 출력과 대조해 "이상한 점이 없나"를 열린 눈으로 판단**한다. 정의하지
않은 문제도 눈에 걸리면 잡힌다.

## 방법 — 회사별 FS vs 엔진출력, 전수, 독립 교차검증

1. **회사별 리뷰 패킷**(`src/backtest/review_packet.py`): 회사마다 (a) 실제 재무제표 주요계정·연도별,
   (b) 회계 항등식(자산=부채+자본), (c) "기타 중요 계정"으로 강등된 material 계정, (d) 엔진이 낸 신호를
   한 블록으로 만든다.
2. **두 리뷰어가 독립 판단**: 같은 패킷을 두 강한 모델(Claude·Codex)이 **서로 안 보고** 각자 리뷰한다.
   둘이 다르게 짚는 곳이 진짜 봐야 할 곳이다(교차검증).
3. **플래그는 데이터로 재검증**: 리뷰가 "이 숫자가 이상하다"고 하면 곧이곧대로 받지 않고, 원천 DART
   값까지 직접 추적해 확인한다(맹신 금지).
4. **전수**: 다양한 규모·업종(반도체·조선·건설·식품·제약·바이오·금융·REIT·지주 등) 121개 회사 전부.
   이후 표본이 제조에 쏠려 빠졌던 업종(건설·통신·전기/가스 유틸리티·게임/SW·항공·물류·리테일·교육)
   17개 대표 대형주를 더해 같은 방식으로 재검증했다(총 138사). → "## 커버리지" 참조.

## 결과 — 수렴했다

121개 회사를 모두 본 결과, 발견 유형이 **5가지로 닫혔다.** 16번째 회사에서 마지막 새 유형이 나온 뒤,
**105개 회사를 더 봐도 새로운 문제 유형이 단 하나도 안 나왔다.** 이것이 수렴 신호다 — "버그를 다
찾았길 바란다"가 아니라 **"전부 봤고, 문제는 이 5가지로 닫혔다"**가 된다.

```
검증 항목                                  결과
회계 항등식(자산=부채+자본) 위반            138사 전수 0건  → 계산은 정확
정규화 금액 vs 생 DART 값                   전수 0 불일치   → 숫자는 충실
발견된 문제 유형                            5가지로 수렴(아래)
```

## 발견된 5가지 (전부 유한·해결 가능)

| 유형          | 내용                                                                            | 성격                      |
| ------------- | ------------------------------------------------------------------------------- | ------------------------- |
| 매핑 변종     | "당기순이익(손실)"·매출채권/매입채무 조합라벨·매출 변종이 비표준 코드일 때 강등 | 설정 보강                 |
| 진행률 계정   | 계약자산·미청구공사 등이 미등록 → 조선·건설 진행률 사슬 불능                    | 설정 보강                 |
| 극단-% 노이즈 | 0 근처 분모에서 % 가 폭발해 순위 상위 점령                                      | 신호 정렬(신중)           |
| 데이터 오류   | 한 회사(소프트센) 2022 원천값이 10⁶배 오류                                      | 데이터 가드               |
| 스코프        | 금융·REIT·SPAC는 매출·재고 구조가 없어 신호 0                                   | 도구 스코프 밖(버그 아님) |

핵심은 **계산은 단 한 번도 안 깨졌다는 것**(항등식 0 위반)이다. 문제는 *계정 매핑·순위·데이터 위생*이지
*계산*이 아니다. 즉 무한히 나오는 게 아니라, 닫힌 목록이다.

## 교차검증의 가치 — 두 리뷰어가 메운 빈틈

- **공통 발견(높은 확신)**: 매핑 변종·진행률 계정·극단-% 노이즈·스코프 — 두 리뷰어가 독립적으로 같이
  짚었다.
- **한쪽만 잡은 것**: 소프트센 데이터 오류는 한 리뷰어가 쓰레기 신호(매출채권 −63,515,952%)를
  보고도 "% 노이즈"로만 분류했는데, 다른 리뷰어가 원천값이 10⁶배 깨졌음을 추적해 근본원인을
  진단했다. 독립 두 의견을 맞댄 덕에 메워진 빈틈이다.

## 커버리지 — 빈 업종까지 채웠다

처음 121사는 다양했지만 **제조(전자·기계·화학·의약·금속)+도매에 쏠려** 있었다. 규모(소형~초대형)와
시장(유가·코스닥)은 고루 덮였지만, **건설·통신·전기/가스 유틸리티·게임/SW·항공·물류·리테일·교육**이
0~1사뿐이었다. 검증이 안 본 회사 종류가 있으면 "전수"라 말할 수 없으므로, 이 빈 업종의 대표 대형주
17개(현대건설·GS건설·DL이앤씨·HDC현산·SKT·KT·LG U+·한국전력·한국가스공사·엔씨·크래프톤·카카오·
펄어비스·대한항공·CJ대한통운·이마트·메가스터디교육)를 더해 같은 홀리스틱 리뷰를 돌렸다.

결과: **17개 회사 모두 항등식 0 위반, 데이터 스케일 오류 0, 새로운(6번째) 문제 유형 0.** 발견은 기존
5가지 안에 그대로 들어왔다 — 수렴이 더 넓은 업종에서도 유지됐다(총 138사). 특히 의미 있는 두 가지:

- **건설 4사가 진행률 계정 문제(매핑 보강 대상)를 정확히 재현했다.** 계약자산·미청구공사·공사매출·
  분양매출이 회사마다 다른 라벨("유동계약자산"·"공사수익"·"건설계약으로 인한 수익")로 적혀 "기타 중요
  계정"으로 강등됐다. 이는 도구의 진행률 매핑 보강이 실제 건설업에서 필요함을 실증한다.
- **통신·게임은 매출원가·재고 구조가 없다**(서비스업). 제조 가정의 도구가 이런 업종에선 일부 계정이
  비는 것은 버그가 아니라 스코프이며, "조용히 0"이 아니라 명시할 항목이다.

## 검증이 실제로 고친 것 — 결함 수정 임팩트 (before → after)

검증은 "괜찮다"를 확인하는 데 그치지 않고, 발견한 결함을 실제로 고쳐 데이터를 바로잡았다.
대표 사례를 before → after 수치로 남긴다.

| 결함                   | 증상(before)                                                                                    | 수정 후(after)                       | 무엇을 했나           |
| ---------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------ | --------------------- |
| 금융업 재무상태표 매핑 | 미매핑 금융자산으로 BS 항등식이 **−52조** 불균형                                                | **+0.08조**(항등식 회복)             | 금융업 canonical 신설 |
| 자본변동표 부호 오류   | member 셀 부호 반전 시그니처 **334건**                                                          | **0건**                              | member-sign 정렬 수정 |
| 외화(USD) 재무         | USD 금액을 원화로 가정해 약 1,300배 축소, 항등식은 안 깨져 **silent 통과**(5,792행/39 회사연도) | 게이트가 비원화 재무를 **분석 차단** | 통화 단일성 게이트    |
| 게이트 hollow-PASS     | BS 통째 결손·SCE 표준화 실패가 "차이 0"으로 **통과로 둔갑**                                     | 빈 검산은 통과 아닌 **FAIL**로 차단  | 게이트 바닥 규칙      |

핵심은 이들 모두 **분식 지식이 아니라 일반 회계·통계 원칙**으로 고쳤다는 점이다(특정 사건이
통과하도록 맞추지 않음). 특히 hollow-PASS·통화 차단은 "빈 결과·외화를 정상으로 둔갑시키던"
조용한 오류를 드러내 막은 사례다.

## 신뢰 관점

이 검증이 답하는 것은 "버그가 0개임을 증명"이 아니라 — 그건 불가능하다 — **"빈 업종까지 채운 138개
회사를 전부 재무제표와 대조해 눈으로 봤고, 문제는 이 5가지로 닫혔으며, 계산은 전수 0 위반"**이다. 발견된
5가지는 모두 유한하고 해결 가능한 항목이며, 수정 목록은 `FIX_LIST.md`에 정리돼 있다.

## 전과정 E2E 평가 (대주산업) — 수정 before → after

전수 홀리스틱(신호 엔진)과 별개로, 한 회사를 **수집→정규화→온보딩→Phase1→Phase2**까지 전과정으로
돌려 산출물(전처리·검토 큐·의심건 카드)을 독립 회계분석과 대조했다(대주산업 00112457/2024). 이 도구의
목적은 분식 적발이 아니라 **이상 변화·감사인이 볼 검토 큐**를 정하는 것이므로, 평가도 "큐가 정당한가"
기준으로 본다. 산출물: `data/backtest/_E2E_EVAL_00112457_2024.json`.

평가에서 두 결함이 드러났고 수정 후 다시 측정했다.

| 항목                   | before                                  | after                             |
| ---------------------- | --------------------------------------- | --------------------------------- |
| 전처리(원문 vs 정규화) | 25계정 1:1 대조 불일치 0                | 0 (불변)                          |
| 자본변동표 거짓양성    | "자본총계 95% 재작성" 거짓 카드 **3건** | **0건**(restatement 신호 수정)    |
| 이상변화 큐 누락       | 설비투자 급증(+177%)이 큐에 **미진입**  | 큐 **진입**(유형자산취득 카드)    |
| 의심건 카드            | 16(거짓양성 3 포함)                     | 14(거짓양성 0)                    |
| 회귀(테스트)           | —                                       | pytest 356 → **363 통과**(무회귀) |

- **거짓양성 제거**: 자본변동표 구성요소(자본잉여금)를 자본총계 전기값으로 오인해 "대규모 하향 재작성"
  거짓 신호를 내던 것을 신호 단에서 차단했다. 실제 자본총계는 정상 증가(재작성 없음)였다.
- **이상변화 큐 진입**: 분식은 아니지만 감사인이 볼 만한 변화(설비투자 +177%)를 담을 유형이 없어
  큐에서 빠지던 것을, 유형 분류에 "기타" 안전판을 둬 큐에 올렸다. 이때 반박 에이전트가 "정상 우세"로
  판정해 **큐엔 두되 하단**에 배치한다 — 정당한 의심점이 위, 비-분식 이상변화는 아래라는 순위가 지켜진다.
- 핵심은 **거짓을 빼고 놓치던 이상변화를 넣되, 정상 가능성은 병기**한다는 것이다(정상우세 플래그).
