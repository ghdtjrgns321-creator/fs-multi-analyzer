# 온보딩 LLM 모델 비교 — 왜 gpt-5.4를 쓰는가

> 새 회사를 넣을 때 Phase1(수집·정규화) 전에 한 번 돌리는 "LLM 전수검수"가 어떤 모델을
> 써야 하는지를, 고위험 회사 10곳에서 두 모델을 직접 맞대 정한 기록이다.
> 검수 단계의 위치·역할은 [FEATURES.md](FEATURES.md)·[MULTI_AGENT.md](MULTI_AGENT.md),
> 분식 검증 방법은 [BACKTEST.md](BACKTEST.md)를 참조한다.

## 한 줄

같은 재무제표 데이터·같은 9개 점검 관점을 주고 **모델만 바꿔** 돌려보니, **gpt-5.4**가
분식 신호를 잡는 데 기존 검수와 대등하거나 일부 유형에서는 더 잘 잡았다. 그래서 화면(UI)
온보딩의 LLM 전수검수는 gpt-5.4로 정했다. 단점 하나(표시 착시로 인한 헛신고)는 표시 방식만
고치면 사라진다.

## 무엇을, 어떻게 비교했나

- **대상**: 위험이 많을 것으로 예상한 10개사 — 분식 확정 사건 6곳(정답지) + 재무위험 의심 4곳.
- **공정성**: 두 모델에 **똑같은 입력**(회사별 여러 해 재무 요약 dump)과 **똑같은 질문**
  (9개 점검 관점)을 주었다. 다른 건 **모델 하나뿐**이라 순수하게 추론력만 비교된다.
- **A(기존 검수)**: 이번 작업에서 내가 돌린 통독 결과.
- **B(gpt-5.4)**: 화면 온보딩이 실제로 쓰는 경로(`run_llm_holistic`)로 새로 돌린 결과.
- **검증**: B가 "새로 찾았다"는 것은 곧이곧대로 믿지 않고, 실제 데이터(회사별 DB)로 직접
  맞는지 확인했다.

## 핵심 결과 — 분식 확정 6곳에서 누가 더 잘 잡았나

```
회사            분식 유형                       A(기존)            B(gpt-5.4)            우위
두산에너빌리티  진행률 과대 → 매출 소급정정     매출 재작성 정밀    공사 수익인식 위험만   A
디아이동일      연결 부당포함 → 자본·수익 과대  못 잡음(정상 판정)  비지배 귀속 이상 포착   B
아스트          재고자산 과대                   재고 미강조        재고가 매출의 3배 포착  B
셀트리온        개발비 자산화 + 재고평가 누락   소급정정만         무형자산·재고 둘 다     B
세토피아        미납입 BW를 납입 처리           위기·손상          위기·BW 집중           무승부
모델솔루션      총액매출 과대 + 결산수정        수익성 둔화        수익성 둔화(+헛신고)    무승부(A)
```

- gpt-5.4가 **기존 검수가 놓친 분식 단서를 더 직접 짚은 곳이 2곳**이었고, 둘 다 실제
  데이터로 사실을 확인했다.
  - 디아이동일: 한 해 순이익 138억 중 모회사 몫이 **0.24억뿐** — 연결을 부풀린 전형적 흔적.
  - 아스트: 재고가 매출의 **3.1배** — 팔린 재고를 비용 처리하지 않고 재고로 남긴 흔적.
- 기존 검수가 더 정밀했던 곳은 1곳(두산에너빌리티, 매출 소급정정을 원문까지 추적).
- 나머지는 비슷했다.

**판정: gpt-5.4의 분식 신호 포착력은 기존 검수와 대등 이상이고, 연결·재고 부풀리기형에서는
오히려 앞섰다.**

## gpt-5.4의 약점 하나 — "표시 착시"에 속는다

- 우리 dump는 89만 원처럼 아주 작은 금액을 큰 숫자로 보여주는 표시 방식을 쓴다(백만 단위로
  안 바꾼 채 원 단위로 둔 행이 섞여 있다). gpt-5.4는 이걸 보고 "숫자 규모가 이상하다 =
  정규화 오류"라고 **잘못 신고**하는 경우가 회사당 평균 4건 나왔다.
- 그러나 실제 데이터를 확인해보면 **전부 정상 매핑**이었다(89만 원짜리 미세 항목을 그대로
  맞게 처리한 것). 기존 검수는 이 표시 방식을 알고 있어서 안 속았을 뿐이다.
- 즉 이 약점은 모델의 추론 결함이 아니라 **우리 화면 표시 방식 탓**이다.

## 결론과 다음 보정

- **온보딩 LLM 전수검수는 gpt-5.4로 채택.** 분식을 잡는 게 핵심 목적인 단계에서 충분히,
  일부는 더 잘하기 때문이다. (덤으로 Phase2 본분석 단계의 6관점·반박 에이전트도 모두 gpt-5.4를
  쓰므로 온보딩~분석 전 구간이 같은 모델로 일관된다.)
- **보정 1건(권장)**: dump 숫자를 **전부 백만 단위로 통일**하면 위 "표시 착시"가 사라져
  gpt-5.4의 헛신고가 없어진다.
- **읽는 사람 주의**: gpt-5.4가 "규모/스케일이 이상하다"고 신고한 항목은, 실제 원래 값을
  확인하기 전에는 결함으로 단정하지 않는다.

## 온보딩 청크선별 비교 — GPT vs 사람(Opus), 그리고 비용

위는 "분식 신호를 잡는 통독"의 모델 비교였다. 여기서는 한 단계 앞, **사업보고서 원문에서
"검토할 공시 종류"(우발·소송·제재·전환사채·특수관계자·계속기업 등)를 골라내는 작업**을
gpt-5.4와 사람(Claude Opus)이 각각 해서 맞대본 결과와, 그때 드는 **시간·비용**이다.

### 무엇을 비교했나

- **대상**: 층화 무작위 10개사(최근 양식 6 + 옛 양식 4). 같은 입력(내용필터된 본문)을 주었다.
- **GPT**: 온보딩이 실제 쓰는 경로로 원문을 읽고 검토관심 청크를 골라냈다.
- **사람(Opus)**: 같은 본문을 직접 읽고 같은 작업을 했다.

### 결과 — 거의 같게 골랐고, 지어낸 근거는 없었다

- **고른 공시 종류가 크게 일치**했다. 사람이 "실제 내용 있다"고 본 종류를 GPT도 거의 그대로
  잡았고, 내용 없는 종류("해당사항 없음")는 양쪽 다 올바르게 뺐다.
- GPT는 위험 단서를 잘 짚었다 — 전환사채 가격 재조정(리픽싱)·콜옵션 회계 감독지침·공정거래위원회
  하도급 신고 과징금·관리종목 지정유예·계속기업 존속 의문을 모두 잡았다.
- **지어낸 근거 0건**: GPT가 인용한 근거 103개 전부가 실제 원문에 있는 문장이었다.
- 약점 둘(가벼움): ① 정상적인 회계기준 전환·소급 비교 주석을 "재작성"으로 1~2건 과하게 표시.
  ② 드문 구조(스팩 합병)를 합병 종류로 표면화하지 못한 곳 1곳. 둘 다 보완 가능한 수준이다.

### 시간·비용 (회사 1곳 온보딩 1회 기준)

- **시간**: 평균 약 **10초**.
- **토큰**: 입력 약 **12,900** · 출력 약 **1,200**. (원문을 통째로 넣지 않고 검토관심 부분만
  걸러 넣어, 통째 대비 입력을 약 1/9로 줄였다 — 그만큼 비용도 줄었다.)
- **돈**: gpt-5.4의 정확한 공개 단가를 이 문서에서 확정하지 못해 **단가를 가정**해 계산했다
  (실제 단가를 넣으면 바로 다시 계산된다. 환율 ₩1,380/$ 가정).

```
단가 가정(USD / 100만 토큰)        회사 1곳        전체 약 5,100곳 1회
입력 $1.25 / 출력 $10              약 ₩38          약 ₩20만
입력 $2.50 / 출력 $10              약 ₩61          약 ₩31만
입력 $5.00 / 출력 $15              약 ₩113         약 ₩58만
```

- **요약: 회사 한 곳당 약 ₩40~110, 10초.** 가진 회사 전체를 한 번 온보딩해도 약 ₩20만~58만이다.
- 주의: 위 돈 액수는 **단가 가정값**이다(실제 gpt-5.4 단가 확인 필요). 추론 기능을 켜면
  출력 토큰이 늘어 비용·시간이 더 든다.

### 판정

온보딩 청크선별도 **gpt-5.4가 사람 판단과 신뢰 수준으로 일치하고 근거를 지어내지 않아 채택할
만하다.** 고정 키워드 목록은 첫 실행용 보조(fallback)로만 둔다. 자세한 표·회사별 결과는
`data/backtest/_S7_ONBOARDING_COMPARE.md`에 있다.
