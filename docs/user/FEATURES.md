# 핵심 기능

> 이 프로젝트가 무엇을 하는가. 누구에게 설명하든 이 문서 하나면 된다.
> 상세 설계는 [../agent/PLAN.md](../agent/PLAN.md).

## 한 줄 설명

공시된 재무제표를 여러 AI가 나눠 읽고 서로 교차검증해서, 감사인이 봐야 할 재무제표
리스크를 근거와 함께 짚어주는 도구. **부정을 확정하지는 않는다** — 검토 후보를 제시한다.

## 풀어서

- 회사가 금융감독원 DART에 올린 재무제표(재무상태표·손익계산서·현금흐름표)와 주석을 자동 수집
- 관점이 다른 6개의 AI(재무 수치·주석·계정 간 관계·시계열 추세·외부 근거·업종 비교)가 각자 독립 검토하고, 코드가 같은
  계정끼리 묶어 점수를 매긴 뒤, 별도 반박 에이전트가 정상 가능성을 따진다
- "매출은 늘었는데 영업현금흐름은 줄었다", "주석에 우발부채 문구가 새로 생겼다" 같은 모순·
  변화를 스스로 찾아 **의심건 카드 목록**으로 리포트
- 마지막 판단은 사람(감사인)이 한다 — AI는 후보를 올릴 뿐 확정하지 않는다

## 진짜 가치는 어디에 있나 — 전처리 엔진

멀티에이전트는 눈에 띄는 앞면이지만, 이 프로젝트의 진짜 가치는 그 앞단에 있다.
사업보고서 원문(raw)을 멀티에이전트가 판단할 수 있는 **잘 정돈된 재료**로 바꾸는
전처리 엔진 — 여기가 핵심이다. 에이전트는 그 위에서 판단만 한다.

전처리 엔진은 **2개 층**으로 되어 있다. 1층이 사업보고서를 파트별로 나눠 읽어 재료로 만들고,
2층(멀티에이전트)이 그 재료를 가로질러 판단한다. 핵심은 **1층과 2층이 따르는 축이 다르다**는 것:
1층은 문서 구조(목차 파트)를 따라 **읽고**, 2층은 분석 주제(수치·흐름·주석 등)를 따라 **판단**한다.

```
 사업보고서 raw (12개 PART)
          │
          ▼   ═══ Layer 1 : 목차 파트별로 나눠 읽어 재료화 ═══
 ┌─────────────────────┬──────────────────────────────────────┐
 │ 재무 결정론 리더        │ 서술 리더 4블록 (LLM — 읽고 인용만, 계산 X)   │
 │ PART III (재무·주석)   │ ②사업·영업(I·II)  ③경영진단·감사(IV·V)      │
 │ 숫자 계산 = 코드        │ ④지배구조·특수관계(VI~X)  ⑤우발·제재(XI)     │
 └─────────────────────┴──────────────────────────────────────┘
   (XII 상세표 = 구조화 API 중복 → 제외)
          │                              │
          ▼                              ▼
   정규화 재무·주석 fact            report_extracts (본문 서술 추출 항목)
   + 신호 계산 + 근거색인          + 완결성 경고(파트/항목 통째 누락 감시)
          │                              │
          └───────────────┬──────────────┘
                          ▼   ═══ Layer 2 : 재료를 가로질러 판단 ═══
        6관점(재무수치·주석·계정관계·시계열추세·외부근거·업종비교) → 교차검증 → 의심건 카드
                                          ↑ 여기가 앞면, 진짜 가치는 Layer 1
```

**Layer 1이 하는 일** — 파트마다 담당 리더가 다르다:
- **재무 결정론 리더**(PART III): 숫자 계산은 코드가 정확히 한다(AI는 산수를 틀리므로).
- **서술 리더 4블록**(LLM): 사업·영업/경영진단·감사/지배구조·특수관계/우발·제재를 각각 전담해 읽고,
  감사 검토 관심 항목을 **원문 수치 그대로 인용**해 뽑는다(계산 안 함). 표의 단위 헤더(단위:천US$ 등)까지
  숫자에 붙여 스케일이 소실되지 않게 한다. 결과는 `report_extracts`에 회사·연도별로 적재된다.
- **완결성 경고**(결정론): 리더가 어떤 파트나 가/나/다 항목을 통째로 건너뛰면 경고한다(누락 감시).

**Layer 2**는 이 재료(정규화 숫자 + report_extracts 추출)를 6관점이 가로질러 보고 의심건 카드를 만든다.
자세한 설계는 [../agent/DISCLOSURE_DECOMPOSITION_DESIGN.md](../agent/DISCLOSURE_DECOMPOSITION_DESIGN.md),
재설계 맥락은 [TROUBLESHOOT.md](TROUBLESHOOT.md)의 2026-07-06 항목 참조.

## 핵심 기능 5가지

| #   | 기능                           | 무엇인가                                                                                                                                                       |
| --- | ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **멀티에이전트 교차검증**      | 6관점(재무 수치·주석·계정 간 관계·시계열 추세·외부 근거·업종 비교)이 독립 검토→코드가 계정별로 묶어 표수(N/4)·점수 산정→전용 반박 에이전트가 정상 가능성 점검, 산출물은 의심건 카드 목록 |
| 2   | **재무제표 간 흐름 추적**      | 매출 → 매출채권 → 영업현금흐름처럼 계정 사슬을 따라 정합성 점검                                                                                                |
| 3   | **공시 변동 탐지**             | 전기 대비 주석 문구 변화(신규 소송·계속기업 불확실성 등)를 잡아냄                                                                                              |
| 4   | **결정론 계산 + AI 해석 분리** | 숫자 계산은 코드가(환각 방지), 의미 해석만 AI가 담당                                                                                                           |
| 5   | **근거 기반 리포트**           | 모든 지적에 숫자·주석 근거 + 반대 가능성 + 다음 감사 절차를 함께 제시                                                                                          |

## 다른 도구와 무엇이 다른가

- 비율만 계산하는 재무분석 도구와 달리, **주석 텍스트와 그 변화까지** 교차검증한다.
- "분식이다"라고 단정하는 대신 **"검토 후보 + 정상일 수 있는 이유"**를 함께 제시해, 오탐의
  책임을 사람 판단에 넘긴다(감사 실무의 2종오류 방지 철학).
- AI가 숫자를 직접 계산하지 않으므로(코드가 계산), **계산 환각이 없다**.

## 한 문장 피치

> OpenDART 공시 재무제표·주석을 수집해 BS-IS-CF 숫자 흐름과 주석 변화를 멀티에이전트가
> 교차검증하여, 감사인이 검토할 재무제표 리스크를 근거와 함께 제안하는 Human-in-the-Loop 도구.
