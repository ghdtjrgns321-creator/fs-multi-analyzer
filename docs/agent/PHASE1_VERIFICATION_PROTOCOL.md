# PHASE1_VERIFICATION_PROTOCOL — LLM 감사 프로토콜 (전수·깊게)

> **핵심 목적**: 딱딱한 pass/fail 분류가 아니다. **에이전트(Claude)가 LLM으로서 회사 데이터를 직접
> 읽고 감사관처럼 이상을 판단**한다. 이번 세션의 큰 발견(lump 소실·정정공시 오염·SCE 부호)은 임계검사가
> 아니라 **에이전트가 데이터를 보고** 잡았다. 임계검사는 바닥(floor)일 뿐, 본질은 LLM 판단.
>
> "검증 완료"를 함부로 선언하지 않는다. 아래 차원을 **빠짐없이** 보고, 안 본 차원은 ⬜로 남긴다.
> 설계 프레임은 [PHASE1_INTEGRITY_PLAN.md](PHASE1_INTEGRITY_PLAN.md), 데이터 출입은
> [DATA_PIPELINE_SCOPE.md](DATA_PIPELINE_SCOPE.md). 작성 2026-06-10.

## 사용법

```
PYTHONPATH=. uv run python data/backtest/_p1_company_review.py <corp_code> [year]
```
→ 한 회사연도의 전 차원 데이터 dump 출력. **에이전트가 그 dump를 읽고 아래 관점으로 판단**한다.

**운용 원칙**:
- **검사 대상으로 명시된 집합(분식 회사연도 등)은 전수다 — 대표·표본 금지**. "대표 1~2개만 보고 통과"는
  §9 hollow-PASS·§10 조용한 다운스코프다. 전수는 배치 러너 `_p1_review_all.py`(정답지 positive·runnable
  전수)로 **강제**하고, 기계검사 바닥(완결성·항등식·주요표·순이익·주석) PASS/FAIL을 먼저 깐 뒤
  `_review_dumps/_ALL.txt`를 **전수로 읽고** 판단한다. (전체 5,000사 모집단은 floor로 flag→flag된 것 깊게.)
- **데이터 완결성이 먼저**: 하니스 §0이 필수 테이블(normalized·sce·**note_facts_classified**) MISSING/빈을
  FAIL로 못 박는다. 본문만 보고 주석 누락을 "정상"으로 넘기던 사고(2026-06-10)의 재발 방지.
- **데이터당 의심**: 곧이곧대로 "0이면 OK" 말고, 수치가 말이 되나·숨은 결함은 없나 해부(§9).
- **발견은 즉시 기록**: 새 이상은 이 문서 "발견 이력"에 추가.
