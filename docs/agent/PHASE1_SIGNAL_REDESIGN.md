# PHASE1_SIGNAL_REDESIGN — 다축 이상 프로파일러 단단설계

> 신호엔진을 "사람이 정한 변화율 룰 + 임계 리터럴의 집합"에서 "모든 계정에 다축 이상점수를
> 전수 계산하는 프로파일러"로 전환한다. 룰 열거 패러다임의 무한 땜빵(놓칠 때마다 룰 추가)을
> 끝내고, 변화 탐지를 §3("계산은 코드, 발견은 LLM") 철학으로 끝까지 코드에 둔다.
> 발단: E2E 평가#1(`data/backtest/_E2E_EVAL_00112457_2024.md`)에서 capex 급증·관계기업
> 추세감소를 신호엔진이 강조 못 해 6관점 전부 놓침 → 근본은 "룰 열거"임을 확정.

> **포지셔닝 고정**: 부정 확정 아님. 프로파일러는 "검토 후보의 이상 강도"를 점수화할 뿐,
> 모든 후보는 반박·정상설명·확인질문·다음절차를 거친다(Phase2 불변).

## 1. 현재 한계 — 룰 열거 패러다임

신호 생성이 전부 "config 룰 + 임계 리터럴"이다:

| 모듈           | 신호                                            | 임계(리터럴)                     | 한계                      |
| -------------- | ----------------------------------------------- | -------------------------------- | ------------------------- |
| `red_flags.py` | growth_divergence·single_yoy·direction_mismatch | divergence_pp 50·yoy 50%         | 관계사슬(config 쌍)만     |
| `universal.py` | universal_yoy·mix_shift·z_score·cfs_ofs_gap     | yoy 50%·mix 5pp·z 2·floor 자산1% | 룰 3개 + **floor 이진컷** |
| `ratios.py`    | 비율 17종                                       | 카테고리별                       | 수준 신호 약함            |

병의 본질: **사람이 "무엇이 이상인지"를 룰로 열거하는 한, 열거 안 한 이상은 영원히 사각이다.**
- capex 급증: YoY +177%인데 **floor 경계**(전기 1,027 < 자산1% 1,113)에서 `_valid_yoy_base`가 차단.
- 관계기업 감소: YoY -10% < 50% → "단년 급변" 룰엔 안 걸림. **다년 추세를 볼 축 자체가 없음.**
- 두 계정 다 account_series로 LLM에 전달됐으나, 신호 강조가 없어 6관점 전부 미선택
  (LLM은 525행에서 YoY를 스스로 계산하지 않는다 — 계산은 코드 몫).

A(Δ금액)·B(추세) 룰을 추가하는 것은 같은 패러다임의 연장(땜빵)이다. 근본은 패러다임 전환이다.

## 2. 전환 개념 — 전 계정 다축 프로파일러

```
모든 계정·비율 (account_level_series 전수)
  └ 코드가 각 계정에 다축 이상점수를 전수 계산 (임계 리터럴 없이 분포 기반)
       │  축마다 self(자기 시계열) + peer(동종 분포) 기준선
       ▼
  [다축 프로파일 표]  계정 × {수준·변화금액·추세·변동성·구성비} 점수 + 통합강도
       │
       ├─→ review_queue = 통합강도 내림차순 (개수상한 없음, 결함① 교훈)
       └─→ Phase2 관점 입력 = 프로파일 표 통째 (LLM이 강조분에 안 갇힘)
```

핵심: 신호엔진의 출력이 "룰에 걸린 몇 건"이 아니라 "전 계정의 이상 프로파일"이 된다.

## 3. 축 정의 (기준선 self + peer)

| 축                   | 정의                                  | 기준선                               | 흡수                   |
| -------------------- | ------------------------------------- | ------------------------------------ | ---------------------- |
| ① 수준(level)        | 계정·비율의 절대 위치                 | **peer** 분위수(동종 같은 계정/비율) | (신규)                 |
| ② 변화금액(delta)    | \|당기−전기\| ÷ 자산총계              | self(전기) + peer(변화 분포)         | **A**, floor 경계 소멸 |
| ③ 추세(trend)        | 최근 3~4년 단조성 + 누적변화율/기울기 | self(자기 이력)                      | **B**, 관계기업        |
| ④ 변동성(volatility) | 시계열 표준편차 ÷ 평균(변동계수)      | self + peer                          | (신규)                 |
| ⑤ 구성비(mix)        | 표 내 비중의 전기 대비 변화           | self                                 | 기존 mix_shift         |

- **capex 추적**: ② 변화금액(Δ1,822백만/자산=1.6% — 전기 크기 무관) + ③ 추세(94→1,027→2,849 단조증가) 두 축이 잡는다.
- **관계기업 추적**: ③ 추세(5,204→4,772→4,281 단조감소 -17.7%) 축이 잡는다.
- 비율(ratios)은 ①수준 축의 입력(peer 분위수)으로 흡수된다.

## 4. 정규화 — 임계 리터럴 제거

각 축 원점수를 **분포 기반으로 [0,1] 표준화**한다(임계를 사람이 박지 않음):
- peer 기준 축(①④): 동종 분포에서 **분위수(ECDF/rankdata)** — "상위 N%"는 데이터가 정함.
- self 기준 축(②③⑤): 자기 시계열 통계(누적변화율·기울기·변동계수)를 시그모이드/분위로 [0,1] 매핑.
- 절대 노이즈 가드만 유지(예: 변화금액이 자산의 0.x% 미만이면 점수 감쇠) — 이진컷 아닌 연속 감쇠.

## 5. 통합 방식 — [결정 필요 D1]

축별 점수를 어떻게 합쳐 review_queue 순위를 매길지:
- **(추천) 축별 독립 플래그(OR) + 통합강도**: 어느 한 축이라도 꼬리(상위 분위)면 후보로 올린다
  (놓침 최소 — 결함①·§9 정신). 정렬은 통합강도(축 점수의 가중합 또는 L2 norm).
- (대안a) max: 최대 축 점수로 순위. 단순하나 "여러 축 동시 약신호" 정보 손실.
- (대안b) 가중합만: 가중치가 새 임계 땜빵이 될 위험.
- → 추천: OR 플래그(후보 포함 판정) + 가중합(정렬). 가중치는 균등 시작, 백테스트로 보정.

## 6. floor 처분

이진 컷(`abs(amount) ≥ 자산1%`) **폐기**. 대신:
- 변화금액 축에 **연속 감쇠**(작을수록 점수↓)로 흡수 → capex 같은 경계 케이스 절벽 제거.
- 아주 작은 절대금액(노이즈)만 약한 하한으로 감쇠(완전 컷 아님).
- `_valid_yoy_base`(전기 floor 미달 차단) **제거** — 변화금액 축은 전기 크기에 의존하지 않으므로 불필요.

## 7. 기존 신호 처분 (ripple) — [결정 필요 D2: 완전대체 vs 하이브리드]

| 모듈/신호                                  | 처분(추천=하이브리드)   | 이유                                                           |
| ------------------------------------------ | ----------------------- | -------------------------------------------------------------- |
| `universal.py` yoy·mix·z                   | **다축으로 흡수(폐기)** | ②③⑤축이 일반화해 대체                                          |
| `universal.py` cfs_ofs_gap                 | 유지 또는 축화          | 연결/별도 괴리는 별 차원                                       |
| `red_flags.py` growth_divergence·direction | **유지**                | 계정 간 "관계 모순"은 단일계정 다축으로 환원 불가(도메인 지식) |
| `ratios.py`                                | 유지                    | ①수준 축의 입력                                                |
| `restatement.py`                           | 유지                    | change 관점 전용                                               |

- 영향 파일(grep 21개 중 src): `universal.py`·`red_flags.py`·`mvp1.py`·`ratios.py`(생성),
  `integrated.py`·`company_report.py`(통합), `materials.py`(LLM입력), `benchmark.py`(peer),
  `run_backtest.py`(회귀), 관련 tests.
- D2 추천: **하이브리드** — universal 룰만 다축 대체, 관계사슬·비율·정정은 유지·통합. 완전대체는
  관계 모순 손실 + 회귀위험 과대.

## 8. LLM 입력 변경

`numeric/flow/change_material`이 받던 `review_queue_reference[:10]` + `account_level_series`(raw 525행)를
**다축 프로파일 표**로 보강: 계정행마다 축별 점수 + 통합강도 + 어느 축이 꼬리인지 태그. LLM은
raw에서 산술하는 대신 "코드가 계산한 이상 프로파일"을 해석 → 강조분 앵커링 탈피(§3 철저화).

## 9. 회귀가드 + 단계 (TDD)

**회귀 baseline (악화 0 필수)**:
- 백테스트 분식 recall **5/6**·FP **0**(현재값, `src/backtest/run_backtest.py`). 재설계 후 동일·이상 유지.
- 분식 16사 신호 깔때기(sj_div별)·기존 단위테스트(test_universal_signals·test_red_flags) 무회귀.
- capex·관계기업 회복 검증: 재설계 후 둘 다 review_queue 상위·관점 material 강조에 등장.

## 10. 데이터 제약 (솔직히)

- **4년 시계열**: 추세 기울기·변동성은 3~4점이라 약하다 → 단조성 + 누적변화율로 보완, 점수 신뢰도 가중.
- **peer DB 커버리지**: peer 없는 계정/업종은 self 축만으로 graceful(peer 축 결측 시 통합강도서 제외).
- false positive↑ 가능 → Phase2 반박·확신도로 거름(설계 불변).

## 11. 확정 결정 (grill 2026-06-21)

- **기준선**: self(자기 시계열) + peer(동종 분포) 둘 다.
- **D1 통합 방식**: **OR플래그 + 가중합 정렬** — 어느 축이든 꼬리면 후보로 포함(놓침 최소,
  결함①·§9), 정렬은 가중합(균등 시작·백테스트 보정).
- **D2 기존 신호 처분**: **하이브리드** — `universal` yoy/mix/z만 다축 흡수·폐기.
  관계사슬(`red_flags` divergence·direction)·비율(`ratios`)·정정(`restatement`)·cfs_ofs_gap은 유지·통합.
- **D3 꼬리 임계**: **분포 상위 분위(개수상한 없음)** + 절대 노이즈 가드만. 고정 컷·상위 N개 아님.

## 11b. 구현 중 발견 (S2)

- **mix(구성비) 보완효과**: 순위 기반 정규화에서 한 계정(예 관계기업)이 감소하면 그 비중을
  흡수하는 최대 계정이 mix 축에서 2위로 올라 같이 flag된다(보완·complement). 실데이터(118계정)에선
  감소분이 다수에 희석되나, 작은 분포에선 거짓 후보가 된다. **대응(S3/calibration 백로그)**:
  mix는 변화 축(delta/trend/volatility)과 달리 절대 비중변화 하한 가드 또는 complement 억제 필요.
  현재 OR플래그는 mix 단독으로도 후보를 만드므로, mix 가중·게이트는 백테스트로 보정한다.
- **tail 기본 0.8**: 작은 분포에선 거칠다(2위≈0.81). 실데이터(큰 분포)에선 상향 가능 — config화.

## 11c. fitting 점검 발견 (분식 6사+정상 2사, `_e2e_fitting_check.py`)

**fitting 아님 확증**: 다축은 capex/대주 전용이 아니라 분식계정도 일반 포착(4/6 분식사 1+:
아스트 재고·매출원가, 셀트리온 재고·무형, 모델 매출·순이익, 두산 매출). flagged% 25~50% 안정.
코드에 corp/계정 리터럴 0. **그러나 점검이 더 중요한 3 갭을 드러냄(S4 전 보강)**:

- **G1 OR플래그 구멍**: strength(가중합)는 높은데 단일 축이 tail 미달이면 flagged 안 됨
  (두산 충당부채 str 0.63·디아이 수익 0.56인데 미flag). → D1 보강: **OR(단일축 tail) ∪
  (strength 상위 분위)** 병행으로 "여러 축 동시 중강도" 후보를 살린다.
- **G2 분식 미포착**: 디아이동일 0/4·세토피아 0/2(둘 다 기존도 '변동미미'). peer 수준축(S4)·
  G1 보강으로 회복 시도. S6 백테스트서 recall 5/6 유지 최종 확인.
- **G3 분식계정 미존재**: 미청구공사·자기자본·개발비 등이 account_level_series에 없어 다축 무력
  (정규화 매핑/series 필터 별개 이슈). S6서 영향 측정 — 다축 책임 아니나 recall에 영향.
