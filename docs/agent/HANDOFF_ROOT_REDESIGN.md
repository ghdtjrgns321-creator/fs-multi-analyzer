## 근본 원인 — 세 사각은 한 뿌리

세 개가 별개 버그가 아니라 **하나의 설계 선택의 세 그림자**. 도구의 분석 축 =
**"연결재무제표(CFS) 본문 계정의 전년대비 변화"**. 그 축 밖은 전부 사각:

| 사각      | 막힌 코드 위치                                                                                                                                                                                                                   | 막힌 진짜 이유                                                                                                |
| --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 별도(OFS) | `src/report/company_report.py:227` `_primary_fs_div` → CFS 있으면 CFS만. 호출 2곳(:200 `_account_level_series`·:243 `_top_unmapped_material_accounts`). 실측 series fs_div=CFS 467·OFS 0                                         | 연결+별도 중복 회피용 "대표 하나" 선택 = **데이터 정리 편의**(분석 필요 아님)                                 |

### 왜 138사 전수검증(VERIFICATION.md)에선 안 터졌나
그 검증은 **"있는 걸 맞게 계산하는가"**(항등식·정규화 충실도)를 봤고 통과함. 그러나 그것도
**도구 안에서** 돌았다 — 도구가 OFS를 안 실으면 도구로 OFS를 검증할 수도 없다(자기참조,
§10 "도구 경계 ≠ 감사 경계"). 이번에 사용자가 시킨 "raw 원본을 LLM이 직접 다 봐라"가
**도구 밖 검증**이었고, 그래서 커버리지 사각이 비로소 드러남. 검증 방식을 바꾸니 작동한 것.

## 멀티에이전트가 "반쪽"인 이유 (핵심)

6관점(numeric/note/flow/change/external/industry)의 입력 데이터:

```
numeric  → account_metrics_panel(CFS 본문) + 비율 + latest_signal_snapshot
flow     → account_metrics_panel(CFS 본문) + latest_signal_snapshot + unmapped + 비율
change   → account_metrics_panel(CFS 본문) + latest_signal_snapshot + ratio_time_series
note     → 주석(note_sections·report_review_chunks)  ← grounding이 카드화 차단
external → 외부 URL
industry → peer 벤치마크
```

→ **내부 3관점(numeric·flow·change)이 전부 같은 데이터(연결 본문 패널)를 본다.** 해석 각도만
다르고 입력이 같다. 그래서 그 데이터의 사각(별도·신규)은 **3관점 공통 사각**. 관점을 늘려도
안 보이는 건 똑같이 안 보인다. note만 다른 데이터(주석)지만 grounding이 막는다.

**결론: 멀티에이전트의 다양성이 "해석 다양성"에만 있고 "데이터 차원 다양성"엔 없다.**
6관점이 사실상 numeric 하나로 수렴 → 사용자가 느낀 "쓸모없다"의 정체.

## 해결 방향 — 관점 = 데이터 차원 매핑 (땜빵 아닌 근본)

세 사각을 따로 고치는 게 아니라, **각 관점이 자기 차원의 데이터를 받고 grounding도 그 차원을
검증하게** 데이터 파이프를 차원별로 여는 한 가지 수정:

```
numeric  → 연결 본문 수준/변화          (지금대로)
flow     → 연결 ↔ 별도 교차, BS↔CF 흐름   ← OFS 열기
change   → 신규발생/재개 포함 시계열      ← 분모0 신호(전기결측 = 신규발생 flag) 열기
note     → 주석 우발·특수관계자·보증       ← 주석 grounding(note_facts 인덱싱) 열기
```

이러면 관점마다 **다른 차원**을 보므로 멀티에이전트가 제값을 하고, 3사각이 동시에 닫힌다.

### 설계 시 결정 필요(트레이드오프)
- **OFS 열기**: 별도 전체 투입 시 프롬프트가 방금 줄인 것(관점당 199k→94k, 결함② 수정) 다시 증가.
  → "연결과 차이 큰 계정만" 같은 선택적 투입 설계 필요.
- **분모0 신호**: delta_score를 전기결측 시 current/asset로 줄지, "신규발생" 별도 flag로 줄지.
- **주석 grounding**: note_facts.tsv를 account_index에 병합 vs 주석 전용 검증 경로 신설.
- 예상 추가 사각(같은 축 그림자): 분기/반기(연간만), 사업부문 세그먼트, 절대수준 이상.
