# 사업보고서 해체 엔진 — 2-Layer 재설계 (설계 단일 출처)

> 온보딩+Phase1/2를 "읽기(Layer 1) → 분석(Layer 2)" 2계층 멀티에이전트로 재편.
> 상태: **설계**(Layer 1 결정론 뼈대는 Plan A로 구현 완료, 리더·Layer2는 미구현).
> 관련: [PLAN.md](PLAN.md) §3 · [DECOMPOSITION_PLAN.md](DECOMPOSITION_PLAN.md)(Plan A) ·
> 근거 산출물: `data/backtest/_READER_TAXONOMY_VERDICT.md`·`_DECOMP_ROUTING_FULL.txt`(대주·삼성 2사 전수).

## 0. 정체성

raw 사업보고서를 **잘 읽어 정제한 뒤 멀티에이전트에 넘기는 것**이 이 프로젝트의 핵심 가치다.
"읽기"와 "분석"을 두 계층으로 분리한다 — Layer 1이 문서를 부분별로 읽어 핵심을 추출하고,
Layer 2가 그 추출물을 가로질러 흐름·추세·변화·리스크를 판단한다.

> 포지셔닝 고정: 부정을 확정하지 않는다. 모든 Finding은 반대근거·정상설명·확인질문·다음절차를 포함한다.

## 1. 왜 재설계하나 (두 접근을 폐기)

| 폐기 대상                          | 문제                                                                                                                       |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| S7(온보딩 LLM 청크선별)            | LLM이 "포함 여부 + 주제"를 vague 기준으로 판단, 검증 불가                                                                  |
| 단일주제 라우팅(제목→1주제 키워드) | rich section을 억지 버킷 하나로 뭉갬(위험관리→부채유동성만, 파생·신용·환 소실). 주제 taxonomy 자체가 원본에 없는 자의적 틀 |

**근본 해결 = 2-layer.** "주제로 미리 분류"를 버리고 "부분별로 읽어 추출"로 바꾼다. 분류 taxonomy가
사라지니 자의성이 증발한다. 숫자는 여전히 결정론(계산=코드), 서술은 읽어서(발견=LLM) — PLAN §3 준수.

## 2. 핵심 개념 (2-Layer)

```
사업보고서(raw)
   │  [결정론] 섹션 분할 + 섹션→리더 배정 + 커버리지 장부  ← Plan A 구현됨
   ▼
Layer 1 — 리더(읽기·추출): 목차 macro-block 별 담당 리더가 부분을 읽어 핵심 추출
   · 재무=결정론(기존 Phase1/note_facts) · 서술=LLM(파트 목적별 프롬프트)
   ▼  (추출물 = 캐시)
Layer 2 — 분석가(판단): 추출물 + 결정론 숫자를 가로질러 흐름·추세·변화·리스크 판단
   ▼
의심건 카드
```

**Layer 1과 Layer 2는 따르는 축이 다르다** — 이게 설계의 핵심:
- **Layer 1 = 문서 구조(목차 파트)를 따른다** — "이 부분을 부분으로서 이해". 자의성 0(원본 구조).
- **Layer 2 = 분석 테마(특수관계·추세·우발…)를 따른다** — 여러 파트를 가로지르는 판단.

예: 특수관계는 VII(최대주주)·IX(계열)·VIII(임원)·X(대주주)·주석에 흩어져 있다. 이를 **모으는 건 분석(Layer 2)**이지
읽기(Layer 1)가 아니다. Layer 1은 각 파트를 읽어 추출만, Layer 2 특수관계 분석가가 흩어진 추출을 모아 판단한다.

## 3. 결정론 뼈대 (Plan A — 구현 완료)

Layer 1의 "무엇을 누가 읽나"는 전부 결정론이다(판단 없음). 이미 `src/report/section_router.py`·
`src/notes/report_parts.py`로 구현·검증됨(대주·삼성 2사, 항등식 True).

- **섹션 분할**: `split_subsections(part)` — PART 본문을 최상위 "N. 제목" 경계로 subsection 분할(단조증가 번호로 top-level만).
- **리더 배정**: 섹션의 PART 번호 → 담당 리더(§5). 결정론 매핑(제목 키워드 판단 아님).
- **커버리지 장부**: 모집단 = 전 subsection. `모집단 = 배정됨 + 정당제외(해당없음) + 미배정(기타)` 항등식. 미배정>0 경고.
- **구조 제외**: PART III(재무제표+주석)·XII(상세표)는 서술 리더 대상 아님(각각 결정론 재무 리더·구조화 API/스킵).

> **폐기물**: `route_title`·주제 라우팅 YAML(`report_section_routing.yaml`)은 **은퇴**한다(단일주제 버킷팅).
> **생존물**: `split_subsections`·커버리지 장부·III/XII 제외는 리더 배정의 토대로 그대로 쓴다.

## 4. Layer 1 리더 — 목차 macro-block별 5종

사업보고서는 규제상 5개 macro-block으로 배치돼 있다(회사가 준 구조, 자의적 아님). 각 block에 리더 1종.

| 리더                    | 담당 파트            | 추출 초점                                                       | 종류                           |
| ----------------------- | -------------------- | --------------------------------------------------------------- | ------------------------------ |
| **① 재무 결정론**       | III                  | 본표 숫자·주석 fact                                             | 결정론(기존 Phase1·note_facts) |
| **② 사업·영업**         | I, II                | 회사·연결범위·신용평가·제품별매출·가동률·유형자산·위험·파생·R&D | LLM                            |
| **③ 경영진단·감사**     | IV, V                | 경영진 해설·**중요 회계추정**·감사의견·**핵심감사사항(KAM)**    | LLM                            |
| **④ 지배구조·특수관계** | VI, VII, VIII, IX, X | 이사회의결·**내부통제**·지분·임원보수·계열사·**대주주거래**     | LLM                            |
| **⑤ 우발·제재**         | XI                   | 소송·우발부채·약정·**제재현황**                                 | LLM                            |
| (제외)                  | XII 상세표           | 종속사·계열사·타법인출자 상세 = 구조화 API/XBRL 중복 → 스킵     | —                              |

- **전 파트 귀속**(I~XII 미귀속 0): I·II→②, III→①, IV·V→③, VI~X→④, XI→⑤, XII→제외.
- **고가치 4종이 자연 귀속**: KAM→③, 회계추정→③, 내부통제→④, 제재→⑤. 놓칠 자리가 없음.
- **"리더 종류(프롬프트) ≠ 호출 횟수"**: 프롬프트는 5종(유지보수 단순). 호출은 파트/크기별로 나눠 부름
  (큰 파트는 크기가드 걸고 별도 호출 — §7). 서술 리더는 파트 목적에 맞춘 프롬프트를 쓴다(§6 focus).

## 5. Layer 1 출력 스키마 (grill 확정)

각 서술 리더는 자기 파트에서 항목을 뽑아 **동일 스키마 `ExtractedItem` 리스트**로 뱉는다(리더마다 다른 건
프롬프트뿐, 출력 모양은 하나 — Layer 2가 파트를 가로질러 소비하기 쉽게).

```python
ExtractedItem:
    part          # 출처 PART 로마숫자
    label         # 항목명(짧게)
    statement     # 핵심 서술 (원문 수치를 그대로 인용 포함 — 계산·비율 산정 금지)
    evidence      # 원문 근거(위치/인용)
    why_relevant  # 검토 관심 이유(정상설명 가능 전제)
```

- **리더 = 읽고 요약+인용만.** 계산·판단 0. 서술+숫자 혼재는 `statement`에 숫자를 인용으로 담아 해결
  (별도 figures 배열 없음). 정밀 계산은 전부 결정론(Phase1 재무·§7 앵커).
- **왜 계산 안 시키나**: LLM 산수는 틀린다(PLAN §3). 중요 증감은 재무제표 안에 있고 Phase1이 이미 계산.
  본문 전용 수치(가동률·수주)는 맥락 관찰로 충분(감사 큐 목적).
- 항목마다 **원문 근거(evidence)** 필수 → grounding(§9) 양방향 검증. 부정 확정 금지.

## 6. Layer 2 분석가 (기존 Phase2 관점 = 분석 테마별)

- **확정(Q4): 기존 Phase2 6관점을 그대로 유지하고 입력만 교체.** 관점·카드파이프라인·반박·grounding은 453
  테스트 통과한 완성품 → 재사용. 2-layer 변경의 본질은 입력 준비(S7/라우터 → Layer 1 리더) 교체지 분석층 재건 아님.
- Layer 2는 **Layer 1 추출물(report_extracts) + 결정론 숫자(Phase1)**를 재료로 판단(raw 원문·S7 청크 아님).
- 분석 테마가 여러 파트를 가로지름(특수관계 분석가 = ④·주석 추출을 모음).
- 산출 = 의심건 카드(계정/회사/관계 단위, 기존 카드 파이프라인 재사용).

## 7. 토큰 억제 · 완결성(누락 방지) — grill+실측 확정

**토큰 억제 = 가드 불필요(실측 확정).** 삼성 최악 파트(VIII 임원 114K자) 통째 리더 실행 = 입력 73,386 tok·
출력 2,547 tok·₩288·17.6s(1회 캐시). 회사당 서술 리더 합계 추정 ~₩800 1회. **집중 프롬프트가 명세 나열을
"직원 128,846명 요약"으로 눌러 출력을 작게** 만든다 → 리터럴 임계·트림 코드 불필요(`reader_measure.txt`).

**혼재 처리 = statement 인용으로 해결**(§5). 실측서 채무보증 금액·보수 5억 등을 statement에 정확히 옮김.

**완결성(리더가 빠뜨림) = 구조 결정론 앵커 2종**(2차 LLM·신호어목록 없음 — 자의성 회피):
1. **섹션 커버리지**: 실질내용 subsection이 추출물 0개면 경고(split_subsections 구조가 앵커).
2. **가/나/다 커버리지**: subsection 내 "가. 나. 다." 항목별 0추출 경고(regex 결정론, 한 단계 아래).

**폐기 — 물질 금액 커버리지(역grounding)**: 설계 초안의 앵커 3은 실측(대주·삼성 2사)에서 **실제 리더 누락
catch 0·헛경고 198건**으로 무가치가 확인돼 제거했다. 실패 원인 2종: ⓐ 법조문 번호("「상법」제388조")를
388조원으로 오인(條↔兆 동음), ⓑ 표 셀 원단위 금액 범람(자본금변동표 등, 리더가 요약하는 게 정상인 나열).
근본은 **금액의 스케일이 표 헤더("단위:백만원"·삼성 421회)에 있어 셀 숫자만으론 material 판정 불가** —
정규식으로 신뢰 불가한 영역. 대신 **리더가 표 헤더단위까지 인용하도록 프롬프트 수정**(reader.py: "917,000" →
"917,000천US$")해 금액 소실을 원천 차단했고, 금액 누락 감지는 리더 품질로 커버한다.
- **정직한 잔여**: 파트 안에서 특정 금액·서술을 놓친 미세누락은 구조 앵커로 못 잡음(의미 판단 필요). 집중
  프롬프트 품질(실측상 과태료 6백만원·1,012억17백만원까지 포착)+감사인 원문 열람으로 완화, 한계 명시(§10 도구=후보 제시).

## 8. 커버리지 장부 (조용한 누락 차단)

§3의 장부를 리더 배정에 적용. **파트별 배정은 결정론이라 미배정(기타)이 원리적으로 없다**(I~XII 전부 리더 귀속).
장부의 역할은 §7의 완결성 앵커 경고를 표면화하는 것 — "XI.2 우발 섹션 0추출" 등. → 드리프트·누락이 조용히 안 사라짐.

## 9. Grounding (환각 차단) — 기존 재사용

- 추출물 속 **숫자**: EvidenceRef 숫자 grounding(`grounding.py`).
- **정성 주장**: 텍스트 존재 grounding(`_verify_note_suspicion` 확장) — 인용이 원문에 실재해야 통과.
- Layer 1 추출이 원문 근거를 달고 나오므로 Layer 2 카드의 환각을 원문 대조로 탈락.

## 10. 온보딩 위치 · 캐시 (grill 확정)

- **Layer 1 = 온보딩/분석준비 때 1회 실행 → 캐시**. 저장 = **DuckDB `report_extracts` 테이블**
  (`data/companies/{corp}/{year}/analysis.duckdb`, note_facts_classified와 동일 패턴, 회사/연도 격리). Layer 2가 읽음.
- **온보딩 = 게이트(G1~G5) + Layer 1 리더 실행 + 별칭 제안.** 단순해짐.
- **"기타 수동배정 UI" 제거(Q6)** — 파트별 배정이 결정론이라 미배정이 없음. 감사인 상호작용은 **완결성 앵커
  경고 검토**로 대체("이 섹션 리더가 0추출 — 원문 확인"). 배정이 아니라 검토 안내.
