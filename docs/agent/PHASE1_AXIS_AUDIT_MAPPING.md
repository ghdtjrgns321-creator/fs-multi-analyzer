## 1. 판정 원칙 — fitting과 도메인선행을 가르는 선

축 추가가 fitting이 되는 경우는 **"capex/관계기업이 잡히도록 축·임계·가중치를 역산"** 할 때다.
축 자체는 그 두 계정보다 **먼저 존재한 감사 분석 관점**에서 나오면 fitting이 아니다. 판정 기준:

| 검사       | 통과 조건                                                                       |
| ---------- | ------------------------------------------------------------------------------- |
| 도메인선행 | 축의 근거 기준이 AUDIT_BASIS.md에 이미 Must/Should로 등록돼 있다(capex와 무관). |
| 임계 도출  | 임계가 케이스가 아니라 분포 분위에서 나온다(`_midrank_quantiles` → tail).       |
| 독립 회귀  | capex와 무관한 백테스트 6사에서 recall 5/6 + 삼성 FP 14 불변.                   |

## 2. 5축 ↔ AUDIT_BASIS 매핑 (5/5)

코드 함수 실재는 grep으로 확인(아래 §3). 인용 기준·등급은 AUDIT_BASIS.md 행에 실재.

| 축                           | 코드 함수                   | AUDIT_BASIS 근거(등급)                                                 | 도출 논리                                                                                                   |
| ---------------------------- | --------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| delta (변화금액 \|Δ\|/자산)  | `profiler.delta_score`      | ISA/KSA 320 Materiality(**Must**) + ISA/KSA 520(**Must**)              | 변화의 유의성을 % 아닌 **절대금액/규모**로 본다 = materiality 본령(320). %YoY의 소액기저 폭주를 제거.       |
| trend (다년 단조×누적Δ/자산) | `profiler.trend_score`      | ISA/KSA 520 Analytical(**Must**) + ISA/KSA 710 Comparative(**Should**) | 분석적 절차는 **전기 추세·기대치 대비 변동**을 본다(520). 다년 비교는 710. 단년 YoY로는 안 보이는 완만추세. |
| volatility (변동계수 CV)     | `profiler.volatility_score` | ISA/KSA 520 Analytical(**Must**) + ISA/KSA 240 Fraud(**Should**)       | 예상 밖 변동성·불규칙은 분석적 절차(520)와 부정 이상징후(240) 관점.                                         |
| mix (구성비 변화 pp)         | `profiler.mix_score`        | ISA/KSA 520 Analytical(**Must**)                                       | 구성비(common-size) 분석은 분석적 절차의 표준 도구.                                                         |
| peer (동종 분포 수준)        | 미구현(S4)                  | ISA/KSA 520 Analytical(**Must**)                                       | 분석적 절차는 **비교 가능 정보(산업/동종) 대비**를 명시. 자기 시계열 밖 기준점.                             |

→ 5축 전부 근거 기준이 ISA 520(Must)을 공통 골격으로, delta는 320·trend는 710·volatility는 240으로
보강된다. **어떤 축도 capex/관계기업을 출처로 삼지 않는다.**

## 3. 기존 vs 신규 축 (5/5) — 코드 실재 확인

"기존" 축은 이미 `universal.py`가 전 계정에 돌리고 있다(목록 아닌 전수). 신규는 그 위에 추가.

| 축         | 기존/신규        | 기존 대응(grep 실재)                                             | 비고                                                        |
| ---------- | ---------------- | ---------------------------------------------------------------- | ----------------------------------------------------------- |
| mix        | **기존**         | `universal._signal("universal_mix_shift", …)` (universal.py:310) | 임계 5pp 고정 → 분포분위로 전환만.                          |
| volatility | **기존**         | `universal._z_scores → "universal_z_score"` (universal.py:335)   | z≥2 고정 → 분위로 전환.                                     |
| delta      | **신규(재정의)** | 기존은 %기반 `universal_yoy`(universal.py:307)                   | %YoY → **abs/자산**으로 재정의(320 충실). 트리거 fix 핵심①. |
| trend      | **신규**         | 대응 없음(다년 추세축 부재)                                      | 트리거 fix 핵심②. 관계기업 누락의 직접 원인.                |
| peer       | **신규(미구현)** | 없음                                                             | S4 benchmark 연동 전까지 보류.                              |

핵심: **이번에 트리거를 고치는 신규 2축은 trend·delta다.** 둘 다 독립 도메인 근거가 가장 강한
축(아래 §5)이라는 점이 fitting이 아님을 보여준다 — 근거 약한 축을 끼워맞춘 게 아니다.

## 4. 존재≠사용 갭 — ISA 520 gist의 협소 서술

AUDIT_BASIS.md:43의 ISA 520 gist는 현재 **"매출-채권-CF, 재고-원가, 차입금-이자-CF 관계 사슬의
직접 근거"**로 협소하게 적혀 있다. 그러나 본 매핑은 520의 **일반 범위**(전기 추세·구성비·비율·
비교가능 정보 대비 변동 — 분석적 절차의 표준 구성요소)에 기댄다.

→ **갭 인정**: 520이 AUDIT_BASIS에 Must로 "존재"하지만, 현 gist는 trend/mix/peer 일반 분석을
"사용"하는 근거로는 좁다. 구현 전 **AUDIT_BASIS.md ISA 520 gist를 일반 분석적 절차(추세·구성비·
비교)까지 포함하도록 확장**하는 1줄 보강을 선행한다. 이 보강 없이 520을 인용하면 존재를 사용으로
치환하는 것(§9 위반)이 된다.

(delta→320, trend→710, volatility→240 보강 근거는 각 gist가 이미 범위에 부합 — 추가 보강 불요.)

## 5. 신규축 fitting 위험 등급

| 신규축 | 독립 도메인 강도 | 근거                                                                                      | fitting 위험 |
| ------ | ---------------- | ----------------------------------------------------------------------------------------- | ------------ |
| trend  | **강**           | ISA 520(전기 추세) + ISA 710(다년 비교) 양쪽 Must/Should. 추세는 분석적 절차 정의에 명시. | 낮음         |
| delta  | **강**           | ISA 320 materiality = 절대금액/규모. 교과서적.                                            | 낮음         |
| peer   | **중**           | ISA 520(비교가능 정보) 근거는 강하나, benchmark 데이터 부재로 구현 보류(S4).              | 보류로 회피  |

근거 약한 축을 트리거 fix에 동원하지 않았다. **트리거를 고치는 두 축(trend·delta)이 곧 도메인
근거가 가장 강한 축**이라는 정합이 fitting 아님의 핵심 증거다.

## 6. fitting 방지 가드 4개 (구현 시 강제)

| #   | 가드                   | 측정 게이트(실패조건)                                                                                                                                                           |

| G1  | 임계는 분포 분위로만   | `compute_strength`의 tail은 `_midrank_quantiles` 분포에서 도출. capex가 잡히도록 tail 값을 케이스로 역산하면 FAIL. tail 변경 시 사유=분포 통계여야 함.                          |

## 7. 결론 — step 1 진입 조건

- 5축 모두 AUDIT_BASIS 실재 기준(ISA 520 골격 + 320/710/240 보강)에서 도출됨: **확인**.
- 트리거 fix 신규 2축(trend·delta)이 도메인 근거 최강축과 일치: **fitting 아님 증거 충족**.
- 선행 작업: **§4 ISA 520 gist 1줄 확장**(존재≠사용 갭 해소) → 그 후 step 1 구현.
- 구현 내내 §6 G1~G4를 회귀 게이트로 강제.
